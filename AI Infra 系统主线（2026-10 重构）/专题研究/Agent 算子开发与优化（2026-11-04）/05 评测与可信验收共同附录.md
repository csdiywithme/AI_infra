# 评测与可信验收共同附录

这四个方向共享一个约束：搜索越强，越可能找到测试没有覆盖的捷径，或者把计时噪声选成“最优”。有效优化需要同时证明语义符合任务、速度比较公平、最终采用的代码与测量一致。下面是一套用于比较框架的实验设计建议，不是本轮已执行的 GPU 实验。

## 任务契约先于优化

契约应包含输入与输出的 shape、dtype、layout/stride、alias/in-place 语义、随机性、允许误差、运行 stream、目标 GPU、合法的精度变换，以及是否允许离线预处理。模型能否使用库、复用权重、做代数重写，也应提前明确。

优化不能偷偷改变这些条件。但也不能把所有少算都当作弊：如果某个固定任务数学上恒为零，消除冗余可能符合契约；问题在于它不能代表通用 GEMM 或真实训练负载的优化能力。若测试分布碰巧让少算一行也通过，则是另一类问题：实现根本不等价。两者在论文解读时需要分开。

KernelClaw v2 的审计很有说明力：作者发现少算大量归约元素仍能在随机分布下通过容差，以及退化任务允许绕过主体计算，替换相关候选后重新报告均值。因此通过有限测试与符合预期算法语义仍需区分。[作者审计](https://arxiv.org/html/2603.10085v2#S5.SS5)

## 三类评测材料的用途

| 材料 | 最适合回答的问题 | 使用边界 |
| --- | --- | --- |
| KernelBench | 同一任务格式下，不同模型或搜索方法能否生成正确且快的实现 | 固定数据版本、容差、搜索预算、DSL 和 baseline；L3 不自动等于真实 serving |
| robust-kbench | 初始化和输入变化后，原本的高加速是否仍成立 | 更强测试仍不等于排除所有 reward hacking |
| FlashInfer-Bench / Trace | 真实推理算子的 definition、workloads 和 solution 如何对应 | 核对数据版本、实际 traced shapes、目标设备和具体 evaluator，不能用名字代替协议 |

本轮核查的 KernelBench 为 [`423217d9fda91e0c2d67e4a43bf62f96f6d104f1`](https://github.com/ScalingIntelligence/KernelBench/tree/423217d9fda91e0c2d67e4a43bf62f96f6d104f1)。它本身提供 benchmark 与基础工具，明确不以复杂 agent 编排为目标。robust-kbench 固定在 [`078f5bab29934a822268d59a4e707d449abf9b4e`](https://github.com/SakanaAI/robust-kbench/tree/078f5bab29934a822268d59a4e707d449abf9b4e)，增加初始化与输入检查。FlashInfer-Bench 的版本入口为 [`15618a67e8d7b7f49ca61b5ba3b9f26a876d0bee`](https://github.com/flashinfer-ai/flashinfer-bench/tree/15618a67e8d7b7f49ca61b5ba3b9f26a876d0bee)；本轮对其只做格式说明核查，不是完整源码审计。

## 测量层级必须一致

同一个任务可能有几种不同的“时间”：单 kernel GPU 执行、多个 kernel 的 GPU makespan、host 到结果可用的调用时间、完整 forward、服务请求延迟。累计 GPU 活动时间可能重复计算重叠，也可能漏掉等待和 host 开销。

因此应先写清优化目标。若测 isolated kernel，就给 reference 同层测量；若目标是完整调用，候选和 reference 都包含相应 wrapper、必要分配与同步。NCU 用来解释瓶颈，最终性能用另行控制的计时实验。性能证据不应从 profiler 的高开销执行直接移植到常规调用。[NCU 采集与 replay 说明](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html)

Graph、cache、精度和预处理会显著改变比较的意义。W8A16 对 BF16 可以是有价值的系统方案，但需要质量验证，不能被写成同精度 kernel 进步；只测 position 0 的 decode 也不能证明长 KV 场景收益。

## 如何降低搜索选择噪声的影响

在开发集上允许 agent 多轮搜索，最后冻结一个候选，再进行独立 acceptance。不要让 acceptance 的每次结果都继续成为无限试错反馈，否则它也退化成搜索集。

建议用 A/B 成对或 ABBA/BAAB 分块比较，使两版在相近环境中交替执行，并记录原始样本、块次序、GPU clock/温度/功耗条件。ABBA 有助于降低漂移影响，但不是统计显著性证明。接近噪声的改善应报告为未确认，而不是不断重跑直到有一次胜出。

跨 shape 聚合时明确等权还是流量加权，检查最差回退和重点 shape。只用几何平均可能接受少数关键 shape 的明显退化；只用算术平均又可能被极端比值支配。

KernelBench 的 `fast_p` 是“正确且加速比大于 p”的任务比例，失败任务保留在分母中。可以同时报告成功子集的几何均值，但不能把它冒充所有任务收益。[指标定义](https://github.com/ScalingIntelligence/KernelBench/blob/423217d9fda91e0c2d67e4a43bf62f96f6d104f1/README.md#overall-benchmark-metric)

## 一个用于四方向对照的最小实验

建议选择三个算子族，每族两个开发 workload 与一个保留 workload：normalization/reduction、GEMM、attention 或线性注意力子图。shape 来自真实调用；额外加入非整齐边界、不同 stride 和针对性数值分布。任务量只是小规模起点，不支持全领域泛化。

| 对照组 | 保持相同 | 改变什么 |
| --- | --- | --- |
| 基础 coding agent | 模型、工具、任务和预算 | 不加额外领域记忆 |
| Agent 加知识与诊断 | 同上 | 加版本化知识、NCU 解释、失败轨迹 |
| Agent 加受控搜索 | 同上，并报告额外开销 | 加候选档案、分支选择、独立晋升 |
| 专用模型对照 | evaluator 和 workload | 替换模型，同时分别约束 wall time、token 和 GPU 预算 |

token 相同不等于计算成本相同，候选数量相同也不等于 wall time 相同。宜分别给出固定 wall time 与固定候选数的结果，避免一个模型通过更长推理、另一个通过更多编译而被当作公平对照。

每组至少报告：正确率、正确且有效率、开发/保留 workload 的收益、最差退化、GPU 秒、编译时间、模型 tokens、人工介入，以及最终完整应用收益。训练方法另列数据生成、训练和推理成本；这能检验专用模型是否真的摊薄了长期任务成本。

## 最小记录结构

以下字段是建议的记录设计，不是已有软件的通用 API：

```json
{
  "task_contract_hash": "...",
  "reference_hash": "...",
  "workload_hash": "...",
  "candidate_source_hash": "...",
  "build_environment": "...",
  "gpu_allocation_id": "...",
  "measurement_protocol_hash": "...",
  "correctness": {"verdict": "PASS", "artifact": "..."},
  "timing": {"raw_samples": "...", "paired_blocks": "..."},
  "promotion": {"verdict": "RETAIN_BASELINE", "reason": "..."}
}
```

记录必须由工具生成并检查，模型只引用记录。源码封存后再构建与测量；报告生成后若源码变化，候选身份必须变化。编译、运行或提交状态未知时先查 job，避免重复付费执行。跨任务复用的知识保留适用条件和失败样本，测量结果则保留原始 artifact。

## 本轮真正执行的实验

本轮只运行了 `kernel-opt-agent` 的 CPU 格式 gate 反例。固定脚本来自 commit `21f10bbe3c2dc854e533b62fcd306186f88c76c6`；失败/未测量的报告与注释 kernel 仍令其返回 0 并推进到 v1。该项目自身说明 gate 不解析报告内容，所以这个实验说明的是能力边界，而不是声称发现未披露漏洞。

结果见 [gate-audit.json](evidence/gate-audit.json)、[完整 gate 输出](evidence/gate-audit.log)、[复现程序](evidence/reproduce_gate_audit.py)。复现需要先取固定源码脚本，再把本地路径传给程序；程序不会联网下载、执行 kernel、运行 GPU 或调用模型。
