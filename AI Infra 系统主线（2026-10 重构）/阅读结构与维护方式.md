# 阅读结构与维护方式

先读 [[领域地图与覆盖缺口]]，了解研究边界、已有内容和未闭合问题，再按问题进入 `领域综述/` 的 16 篇综述。[[跨领域联系与共同验证]] 解释一个领域的选择怎样改变另一个领域的瓶颈。

| 阅读目的 | 入口与顺序 |
| --- | --- |
| 建立全局认识 | 领域地图 → 关心的领域综述 → 跨领域联系 |
| 补基础推导 | [[00 AI Infra 整体主线]] → 01–09；参数与单位见 [[算例与符号约定]] |
| 判断某项前沿进展 | 对应领域的原理与路线 → 带日期的进展 → 一手来源与未核项 |
| 持续研究 | 地图中的缺口 → 独立发现 → 已知来源追踪 → 深读核验 → 回写领域判断与联系 |

领域综述是持续研究的主体；01–09 是用同一个代码助手建立基础直觉的教学路径。8B 算例帮助理解，不能决定领域地图的边界。

## 进入16个领域之前

如果矩阵乘法、训练更新、Attention 和一次生成尚不熟悉，先沿基础路径读到05，再进入领域综述。已有这些背景时，可以直接从下面的问题开始。每篇开头交代当前对象与所需认识，沿局部算例展开，不要求一次记住整张地图的术语。

| 从什么问题进入 | 建议先读 | 再沿什么联系展开 |
| --- | --- | --- |
| 训练为什么昂贵，怎样减少达到目标的时间 | D01 数据 → D02 并行 → D03 后训练 | D04 改变工作，D08/D10 执行与交换，D12 保住进展 |
| 生成服务为什么会等待 | D05 调度 → D06 状态 → D07 投机 | D04 改变历史与计算，D08/D11 消费状态，D14 改变实时任务 |
| 一份计算怎样高效落到设备 | D08 算子 → D09 编译 → D10 通信 → D11 存储 | D13 的资源比例和后端，D12 的放置与共驻 |
| 模型怎样持续处理真实任务 | D15 在线数据 → D14 多模态/Agent → D16 交付 | D01 的时间与数据身份，D05 的时限，D12 的恢复 |

这些是阅读支线，可以交叉返回。[[跨领域联系与共同验证]] 用具体选择串起它们；领域地图的当前表则保留各域下一项尚待核验的问题。

## 基础教学路径怎样接续

| 章节 | 进入时已有的认识 | 本章建立的新结果 |
| --- | --- | --- |
| [[01 我们究竟在优化什么]] | 要做一个代码助手 | 固定目标、训练数据与一次更新的工作，区分有效结果与执行速度 |
| [[02 一张 GPU 上时间和显存花在哪里]] | 已知需要执行的计算 | 从张量数 FLOPs、字节和存活容量，再得到时间估计及其边界 |
| [[03 一张卡放不下跑不完以后]] | 已有单卡计算图和状态账 | 每次切分后，看本地还缺什么，由此推出数据交换和并行取舍 |
| [[04 模型结构怎样重新分配系统压力]] | 知道矩阵与切分的成本 | 打开 Attention 与前馈层；改变结构后重新计算依赖与状态 |
| [[05 从模型权重到一次生成]] | 知道模型每层在算什么 | 从重复计算推出 KV，再算阶段、批量、容量与每轮时间 |
| [[06 当许多请求同时到来]] | 知道一次生成怎样占用资源 | 加入到达时间与等待，推出调度、路由、缓存与资源拆分 |
| [[07 当生成结果又参与模型更新]] | 已有训练与生成两种执行过程 | 沿改善同一模型的分支，安排生成、评分、更新与版本交接 |
| [[08 当请求变成多模态任务与 Agent]] | 已有单次请求与服务调度 | 回到在线任务分支，加入图片前端、工具反馈和恢复语义 |
| [[09 怎样让整套系统持续交付结果]] | 已有训练池、生成池和工具服务 | 将排队、准备、争用、保存与恢复纳入完整项目的时间账 |

03 中的 token 行切分只解释位置独立的局部计算。跨位置 Attention 在 04 定义后，再讨论长序列为什么还需要交换信息。07 和 08 是同一产品的两条发展分支，不表示所有模型必须按这个顺序进入 RL 或 Agent。

## 正文、案例和依据各放在哪里

主文负责完成一条推导。小表、公式和时间线用于让读者算出结果；它们要有明确条件，并说明哪些成本没有计算。抽象术语在对应现象出现后引入。

16篇综述已经按整篇论证重排：同一算例的结果继续供后文使用，必要的对象转换先作交代；图用于显示时序、所有权、布局或汇合条件。图前说明要追踪的过程，图后解释它怎样影响选择。能用短文字或计算讲清楚的地方继续保留文字，不按章节数量配图。

领域综述把原理、路线、带日期的进展和判断连在正文中：先解释被改变的条件，再说明机制、收益来自哪里、代价转移到哪里。前沿进展本身就是主要研究内容，不能全部藏进附注。01–09 中已有的展开案例继续保留，方便顺序阅读基础解释。

证据卡、候选与覆盖在追踪记录中；[[来源与证据]] 中的旧卡保持冻结，正文链接仍可回到它们。专题研究保留深入报告，入口在建立相应问题后出现。写作与后续修订按 [[写作与审阅准则]] 执行。

## 追踪怎样维护可读性

研究首先判断新证据改变了哪一项条件，再修改相关推导。新机制需要新的前提，就在使用前补上；改变模型、精度、硬件或任务时明确指出。不要把已完成的事件摘要直接塞进尚未讲完的计算过程。发现、跟踪、核验与通知规则继续见 [[追踪规则]]。

维护历史与每轮实际范围见 [[研究记录]]。当前阅读入口及剩余问题以 [[领域地图与覆盖缺口]] 为准；2026-11-04 的编辑修订保留原理、竞争路线、前沿案例和重要反例，阅读/访问过程集中到来源注。正文日期表示本稿维护时间，各来源的研究截止与月度完成标记单独记录。
