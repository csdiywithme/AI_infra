# 01 组织说明：为什么这样分

## 结论先说

我没有按"训练 / 推理 / 硬件"或按讲座目录分章，而是按**过去一年被改写的判断**切文章，再用三条**机制线索**把它们串起来。理由来自研究本身：

1. **变化集中在交界处。** 本轮读到的最重要材料几乎都跨层：PrfaaS 是"模型结构 → 网络带宽 → 调度"；DeepSeek-V4/V4.1 同时改了 attention、KV 布局、落盘、EP kernel、确定性和 RL；Miles 把推理引擎、权重同步、低精度和沙箱放进一个系统。按层切会把一个机制拆碎。
2. **"状态"是贯穿线。** KV、线性层递归状态、Engram 表、RL 的权重增量和轨迹，都在回答同一组问题：谁产生、活多久、放哪层、多大、能否复用、怎样保持一致。所以有 [[T1 状态的生命周期]]。
3. **每个结论都有反转条件。** 每篇末尾都有反转表，并汇总到 [[T3 结论反转条件]]。

## 文章边界怎么定

- 一篇文章 = **一个被改写的判断**。标题尽量是判断本身（"KV 状态变小之后"），而不是名词（"KV Cache"）。
- 每篇固定四段：**workload 要什么 → 为什么能成立 → 代价搬到哪 → 何时反转**，末尾"未解决问题"与"往哪走"。
- 新工作放在它影响的判断旁边，而不是单独放"新闻"。
- 每篇至少一个**可自己复算的例子**，标"我的推算"，把几份一手数字放到同一把尺子上。
- 旧基线（讲座）只在每篇开头交代"当时怎么理解"，完整对照集中在 [[与讲座对照]]。

## 第二版的结构变化（以及为什么）

第一轮把训练并行、数据、多模态、端侧、电力/成本列为缺口。第二轮按"它们是否改写了一个判断"来决定放哪：

| 问题 | 去向 | 理由 |
|---|---|---|
| 训练并行（CP、PP、分布式 Muon）+ 数据管线 | **新章 [[A12 训练并行与数据管线]]** | 指向一个新判断——"recipe（长度分布、优化器）决定并行策略"——不能塞进已有任何一章 |
| 多模态服务 + 端侧推理 | **新章 [[A13 多模态与端侧推理]]** | 两者共享"prefill 算力 / decode 带宽 + 多阶段请求"的机制，单独成章比拆进 A2/A3 更清楚 |
| 电力与成本 | **新章 [[A14 电力与成本]]** | 有一手证据改变了系统决策（功率平滑的能耗代价、工作点决定每瓦结论）；而且与 A8 的"同步"形成跨章机制 |
| SDC、hang、fail-slow | 并入并重写 [[A8 万卡故障与 goodput]] | 改写的是 A8 原有判断，不是新判断 |
| mega-kernel、生成 kernel 验证 | 并入并重写 [[A10 Kernel 语言与编译栈]] | 同上 |
| V4.1 / Qwen3.8 的 Engram、截止时间模型 | 并入并重写 [[A11 条件记忆 Engram]] | 同上，并更正了第一轮一个推断 |
| 硬件新品（MTIA、Trainium3、Helios） | 并入 [[A9 硬件分工化]] | 只强化"分工化"，没有新判断 |
| MLPerf、InferenceX 等公开测量 | 分散进 A5、A9、A12、A14 | 放在它们校验的判断旁边 |

数据/recipe 没有单独成章：本轮读到的一手证据里，只有"优化器选择"和"长度分布"直接改变了系统设计，都放在 A12；后训练"数据即环境"的变化放在 A7。

## 深度怎么分配

- **A1** 是代表作：可追踪的算例（从每 token 字节到集群带宽，第二版加入 V4.1 的 890 B/token 与 72 小时落盘）。
- A2、A3、A5、A6、A7、A8、A10、A11 写到能自己复述推理。
- A12、A13、A14 是第二版新章，证据多为原型或厂商/分析师，篇幅中等，在 [[02 进度与覆盖索引]] 中逐条标出限制。
- A9 证据仍以厂商声明为主，用途是看"押注了什么"。

## 更正的规则（第二版新增）

当新证据推翻旧段落的**结论**（不只是补充数字）时：在原文位置改写，并在文章开头用 `[!warning] 对第一轮的更正` 写明旧说法、新证据和来源；同时在 [[变化记录#第二轮的更正]] 记一行。只是补充的，不加警告框，直接并入论证。

## 为什么没写某些东西

- **不写月度编年史**：时间只用于标注首发、版本变化与核对日期。
- **不重复教科书基线**（DP/TP/PP、FlashAttention 原理、continuous batching）。
- **投机解码**仍没有单独成章：本轮只在 release notes 里看到方法更替（Medusa 移除、块扩散 drafter 与 XPress 精修进入、LPX 外部 drafter），没有读到改变系统判断的测量；留在 [[变化记录]]。
