# A6 数值一致性：确定性从"调试便利"变成 RL 的正确性条件

> [!abstract] 一句话
> On-policy RL 的数学假设是"采样分布 = 训练时计算的分布"。推理引擎为了快，会按 batch 大小、TP 规模选不同 kernel 和归约顺序，于是同一序列的 logprob 在 rollout 与训练端不同——这不是小噪声，而是会让训练崩掉的偏差。过去一年它从博客话题变成了引擎的伞形 RFC、旗舰模型报告的一个小节和顶会论文。

## 0. 旧基线

讲座没有这个主题。2025 年的共识是"温度 0 也不确定，因为浮点不结合 + 批大小变化"，修复手段（batch-invariant ops）被当作可选的调试模式。

## 1. Workload 要什么：错位来自五个源头

| 源头 | 机制 | 谁在处理 |
|---|---|---|
| batch 大小 | 引擎按 batch 选 kernel / split 数 ⇒ 不同归约顺序 | batch-invariant ops；DETENT |
| TP 规模 | 训练 TP=1、rollout TP>1 ⇒ row-parallel 层（o_proj、down_proj）归约顺序不同；Qwen3-8B 在 AIME24 上跨 TP 1/2/4/8 准确率差 >4% | TBIK |
| MoE 路由 | 门控 bmm vs mm 的微小差异把 token 送到不同专家 | R3 路由回放（vLLM RFC、Miles） |
| 线性 attention | GDN 的 chunked（训练）与 recurrent（decode）是**不同算法**，逐位必然不同 | 统一模型定义 + 前向全用 recurrent |
| 稀疏 attention 索引 | DSA 的 top-k 选择不同 ⇒ 看到的 token 不同 | DSA index replay（vLLM RFC） |

## 3. 代价搬到哪里

- **性能**：从 2.4×（早期 demo）到 1.04–1.17×（DETENT 调优后）——开销正在被工程化压低，但 GDN 等线性层仍是 2–5×。
- **维护**：两份模型代码（训练/推理）是"长期维护上脆弱的"（vLLM 博客原话）；统一模型定义又会限制推理端 kernel 选择。
- **适用范围**：DETENT 的一致只在同一部署、同一模型、同一调优元组内成立；FP8 per-tensor scale 跨 batch 仍会破坏不变性。
- **与其它优化冲突**：投机解码、异构芯片（[[A3 分离的下一层]]）、FP4 rollout（[[A5 FP4 进入训练]]）、远端 prefill（[[A1 KV 状态变小之后]]）都会引入新的数值路径。

## 3.1 第二轮：确定性的第二个用途

[[A8 万卡故障与 goodput]] 读到的两篇 OSDI 2026 生产论文把确定性用在了另一个地方：**SDC 检测**。SDCHunter 先让训练逐位确定（步长差 <0.01%），再在流水线 stage 边界比对两个 DP 副本的哈希；AEGIS 用"确定性重计算必须逐位相同"来比对激活指纹。于是确定性同时服务于：

| 用途 | 要求的不变性 | 谁在用 |
|---|---|---|
| RL 训推一致 | rollout 引擎与训练框架之间、跨 batch 大小与 TP 规模 | vLLM RFC、DETENT、TBIK、DeepSeek-V4 |
| SDC 检测与定位 | 同一训练框架内、跨 DP 副本、跨重计算 | SDCHunter、AEGIS |
| 线上服务可复现 / 审计 | 同一部署内跨 batch | 批不变推理 |

**我的判断**：这让确定性的投资回报从"RL 团队的需求"扩大为"任何万卡训练的可靠性需求"。反过来，凡是为速度放弃确定性的设计（split-k、atomics、非确定融合通信），都要同时付出两份代价。

## 4. 何时反转

| 条件 | 结论 |
|---|---|
| 用 importance sampling / IcePop 类修正而非逐位一致 | 可以容忍错位；GDN 研究显示逐位一致没有带来验证集收益——**一致性是必要条件还是只是充分条件，尚未定论** |
| 离线 SFT / 蒸馏 | 不需要 |
| 线上服务确定性（可复现、审计） | 需要，但只要求批不变，不要求训推一致 |
| 高度 off-policy 的异步 RL | 策略滞后本身带来的分布差可能远大于数值错位（GDN 研究在 off-policy=32 时 no-BI 差约 0.065 vs BI 约 0.035） |
