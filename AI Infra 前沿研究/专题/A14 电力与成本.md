# A14 电力与成本：功率变成要调度的信号，"每瓦 token"是一个工作点而不是一个常数

> [!abstract] 一句话
> 这一章只收"一手证据改变了系统决策"的电力/成本问题。两个判断：**(1) 同步训练让整个机房的功率以秒级、几十兆瓦的幅度摆动，于是"功率平滑"成了 GPU 固件、机架电源和训练框架共同承担的功能，并有可测的能耗代价；(2) 推理的"每瓦 token / 每美元 token"对工作点（交互度、并发、精度、MTP、软件版本日期）极其敏感——同一对硬件，换一个工作点结论就能反转，所以比较时必须把工作点写在数字旁边。**

---

## 0. 旧基线

讲座的 invariant："优化不会消灭代价，只会移动代价"。第一轮把电力/经济性列为缺口。2025 年的常见做法是把功率当作容量规划常数（每机架多少 kW），把成本当作"$/GPU-hour × GPU 数"。

## 1. 训练：同步 = 功率摆动

### 1.1 问题有多大

Microsoft、OpenAI、NVIDIA 的联合论文（[arXiv:2508.14318](https://arxiv.org/abs/2508.14318) v2，2025-08-21）【作者测量与模拟；HTML 后半为摘要级】：

- 大规模同步训练的计算阶段接近 TDP、通信阶段接近空闲；GPU 占 GB200 服务器预留功率的一半以上；**单个数据中心内摆动可达几十兆瓦**，周期约 1 秒到几十秒。
- 电网关心的共振频率约 0.16 Hz 到 60 Hz 以上；AI 训练轨迹的 FFT 能量集中在 0.2–3 Hz——正落在长输电线和机组轴系的敏感区间。

### 1.2 三层缓解，各有代价

| 层 | 机制 | 代价（一手数字） |
|---|---|---|
| 软件 | 在通信阶段塞入填充 GEMM，维持功率 | 对主任务开销 <5%，但要大量 CPU 和主机带宽（论文） |
| GPU 固件 | GB200：可编程升降功率速率、最低功率地板（最高 90% TDP）、停止延迟 | 模拟中 90% 地板使总能耗增加 **10.5%**（论文，StratoSim 模拟） |
| 机架储能 | GB300 电源架：电解电容约 65 J/GPU，低需求时充、高需求时放；升功率时限速，降功率时用"燃烧器"缓降 | 在 GB200 机架上训练 Megatron LLM，有/无储能对比**峰值电网需求降 30%**（[NVIDIA 博客](https://developer.nvidia.com/blog/how-new-gb300-nvl72-features-provide-steady-power-for-ai)，2025-07-28，【厂商测量】）；储能不浪费能量，但增加硬件 |

### 1.3 一个可算的例子

**我的推算**（假设，不是论文的数据）：设每步 80% 时间计算（功率 ≈ TDP）、20% 时间通信（功率 ≈ 30% TDP），平均功率 0.8 × 1 + 0.2 × 0.3 = 0.86 TDP。把地板抬到 90%：通信阶段多耗 (0.9 − 0.3) × 0.2 = 0.12 TDP，能耗增加 0.12 / 0.86 ≈ **14%**。论文模拟得 10.5%——同一量级。这说明：**通信占比越高，"用地板换平滑"越贵**；而 [[A4 MoE 通信融合]] 把通信藏进计算、[[A12 训练并行与数据管线]] 减少流水线气泡，顺带也减小了功率摆动的占空比。

> [!important] 跨章机制
> [[A8 万卡故障与 goodput]] 里，"同步"让一张坏卡停住整个作业；这里，"同步"让上万张卡在同一毫秒内一起升降功率。副本级容错、异步流水线（Muon 下可行，见 A12）等"去同步"的设计，在电力侧也有好处——但本轮没有找到量化这一点的一手研究。

## 2. 推理：每瓦 token 是一个工作点

### 2.1 一组公开的、可以拆开的数字

MLPerf Endpoints v1.0（Kimi K3，agentic_combined，结果发布于 2026-11-09；数字引自 [NVIDIA 博客 2026-11-16](https://blogs.nvidia.com/blog/mlperf-training-endpoints-vera-rubin/) 列出的 MLCommons 条目）：

| 系统 | 加速器 | 系统吞吐 | 运行功率 | 每用户交互度 | TTFT P90 | 并发 | 状态 |
|---|---|---|---|---|---|---|---|
| Vera Rubin NVL72 | 32 | 41,414.2 tok/s | 100.89 kW | 50.4 tok/s | 4,673.9 ms | 1,024 | 初步，待 MLCommons 核验 |
| GB300 NVL72 | 48 | 2,210.4 tok/s | 60 kW | 56.2 tok/s | 2,305.1 ms | 48 | 已核验 |

**我的算术**：约 410 vs 37 tok/s/kW，约 11×——这就是 NVIDIA 在财报电话会上说的"10× tokens per watt over GB300 on MLPerf Endpoints"（[Q3 FY27 电话会](https://www.fool.com/earnings/call-transcripts/2026/11/18/nvidia-nvda-q3-2027-earnings-call-transcript/)，2026-11-17）。

但把条件放在数字旁边就能看到：两者的比较基准是"最低 50 tok/s/user 交互度下的每 kW 吞吐"，而 **GB300 那一点是在并发 48 下跑的，Vera Rubin 是并发 1,024；后者的 TTFT P90 是前者的两倍**。这不是错误——MLPerf Endpoints 本来就是按并发扫 Pareto 曲线（[MLCommons，2026-03-19](https://mlcommons.org/2026/03/mlperf-endpoints-gen-ai-benchmarking/)）——但它说明"11×"是**两条曲线上各取一个点**的比值，而 GB300 在更高并发、放宽 TTFT 时能到多少，这两行数字没有回答。

### 2.2 同一对硬件，结论随工作点反转

| 谁说的 | 条件 | 结论 |
|---|---|---|
| NVIDIA（GTC 2026，经 AMD 引述） | DeepSeek R1，FP4，MTP=3，1k/1k，3 月 7 日数据 | GB300 对 Hopper 每瓦 token 50×、每 token 成本低 35× |
| AMD（[2026-03-18](https://www.amd.com/en/developer/resources/technical-articles/2026/the-many-aspects-of-inference-performance.html)，【厂商声明】） | 同一来源（InferenceX），FP8、无 MTP，≥60 tok/s/user | MI355X 每百万 token 成本"明显低于" GB300 |
| InferenceX 比较页（[GLM 5.3](https://inferencex.semianalysis.com/compare-per-dollar/glm-5-3-gb300-vs-mi355x)，页面标注"非官方部署、数据可能修改或过期"） | AgentX 多轮 agent 负载，FP4，按 2026-07 TCO：GB300 $2.31、MI355X $1.50 每芯片小时 | 143–251 tok/s/user 区间 GB300 每美元 token 高 19–40% |
| SemiAnalysis InferenceX v2（[2026-02-16](https://newsletter.semianalysis.com/p/inferencex-v2-nvidia-blackwell-vs)，付费墙，前半可读） | DeepSeek-R1 8k/1k，分离 prefill + wide-EP | MI355X FP8 分离可与 B200 竞争；FP4 分离明显落后；AMD 的问题是"分离 × wide-EP × FP4"的**可组合性** |

**读法**：决定每 token 成本的不是芯片规格表，而是**软件能否把多项优化同时打开**（分离、wide-EP、FP4、MTP），以及你关心的交互度区间。InferenceX 是开源、在真实硬件上用 GitHub Actions 运行、配置变化时重跑的基准（[About](https://inferencex.semianalysis.com/about)），但 NVIDIA 提供了 GB300 访问、AMD 工程师参与了 AMD 配置——它比厂商博客可复现，但不是无利益关系的第三方。

### 2.3 decode 专用芯片的每兆瓦声明

NVIDIA LPX 产品页（2026-09-21 更新）：与 Vera Rubin NVL72 配对，万亿参数模型"每兆瓦吞吐最高 35×"——脚注写明是**预测**，工作负载为 Qwen3-235B、Kimi K2.5、GPT-MoE 2T，32K–400K KV 缓存 token，基线未在可读文本中说明【路线图·厂商预测】。唯一的第三方数字是 Artificial Analysis 测得的单并发速度（见 [[A3 分离的下一层]]），不是能效。

## 3. 电力作为选址与采购约束

- NVIDIA Q3 FY27（2026-11-17）：计划到 2027 年底在澳大利亚建成 2 GW 的"土地、电力与厂房"容量【公司声明】。电力在财报中以 GW 计，与收入并列。
- MLPerf Training v6.0 没有任何功率结果（MLCommons 新闻稿）；KRAI 自述在 Isambard-AI 上训练时约 510 W/GH200 vs 约 700 W/H200【提交者自述，非正式功率测量】。
- AWS Trainium3（GA 2025-12-02）：同一篇官方稿里能效提升既写"4×"又写"40%"（[About Amazon](https://www.aboutamazon.com/news/aws/trainium-3-ultraserver-faster-ai-training-lower-cost)）——厂商能效数字需要逐句核对。
- OSDI 2026 有专门的"Power, Energy, and Sustainability"会话：*Kareus*（训练中同时降动态与静态能耗）、*Hardware Lifecycle-Aware Power Planning*——只读到标题。

## 4. 代价搬到哪里

| 设计 | 省下 | 代价搬到 |
|---|---|---|
| 功率地板 / 填充负载 | 电网冲击 | 能耗（模拟 +10.5%）、CPU 资源 |
| 机架储能 | 峰值需求（−30%） | 硬件成本与体积（约一半 PSU 体积是电容） |
| 高并发换每瓦吞吐 | 每 token 能耗 | TTFT（Endpoints：2.3 s → 4.7 s） |
| FP4 + MTP + 分离 + wide-EP | 每 token 成本 | 软件可组合性、数值一致（[[A6 数值一致性]]）、精度风险（[[A5 FP4 进入训练]]） |

## 5. 何时反转

| 条件 | 结论 |
|---|---|
| 训练通信占比低（大 batch、通信被藏住） | 功率摆动小，平滑的能耗代价小 |
| 小规模集群 | 摆动以千瓦计，电网层面不成问题；只剩机架级供电约束 |
| 关心低延迟（高交互度、低 TTFT） | 高并发换来的每瓦优势不可用；比较应在同一 TTFT/交互度约束下做 |
| FP8、不开 MTP、早期软件版本 | 厂商之间的成本排序可能反转（AMD vs NVIDIA 3 月数据） |
| 按租赁价而非 TCO | InferenceX 用的是超大规模采购 TCO；租赁价比例不同会改变每美元结论 |
