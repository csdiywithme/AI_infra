# A9 硬件分工化：芯片按"训练 / 推理 / prefill / decode"拆开，scale-up 域越做越大

> [!abstract] 一句话
> 2026 年三家主要厂商都在把一个"通用加速器"拆成按阶段分工的产品线：Google 把第八代 TPU 拆为训练用 8t 与推理用 8i；NVIDIA 给 Vera Rubin 配上 decode 用的 Groq 3 LPX、撤下 prefill 用的 CPX；华为把超节点做到 1024 卡。与此同时，开放 scale-up 标准（UALink、ESUN）进入了"规范已发布、首批产品出现、互操作未证明"阶段。

> [!warning] 读法
> 本篇大多数数字是**厂商声明**，没有可复现的测量条件。它们的用途是告诉我们厂商**押注了什么 workload**，而不是性能。

## 3. 国产硬件的软件栈已跟上旗舰模型

- 招商银行在国产 NPU（文中配置指向昇腾）上用 SGLang 0.5.9 跑 DeepSeek-V4-Flash：PD 分离，2 个 prefill + 2 个 decode 实例，各 16 卡 EP=16，用 RoleBasedGroup（K8s CRD）编排；只给出运维数字（原地升级 3–4 min vs 重建 5–8 min）（[InfoQ](https://www.infoq.cn/article/FDIT4N6S583uNKGmUm8F)，2026-06-10）【用户自述】。
- 华为云社区：Kthena（Volcano 社区）+ vLLM + Mooncake connector 在昇腾上做 DeepSeek-V4-Flash PD 分离，只有配置无性能数字（[博客](https://bbs.huaweicloud.com/blogs/477601)，2026-05-13）。
- DeepSeek-V4 的融合 EP kernel 在昇腾上验证；DeepGEMM-Ascend 于 2026-09-30 独立开源；SGLang v0.5.19 提供 Ascend Kimi-K3 指南。

## 3.1 哪些数字是第三方测的

本章的规格几乎全是厂商声明。第二轮找到的、能拿来校验的公开测量只有三类，都在 [[A14 电力与成本]] 详述：MLPerf Training / Inference / Endpoints（规则审计、提交者自报、部分成绩标"初步"）；SemiAnalysis InferenceX（开源、真实硬件运行，但厂商提供了访问和工程支持）；Artificial Analysis 的单并发速度测量。**没有一个覆盖 LPX 的能效、MTIA 或 Trainium3 的公开对照。**

## 4. 何时反转

- **prefill 主导负载**：SRAM 型 decode 芯片价值下降。
- **模型结构变化**：若 hybrid/压缩 attention 让 decode 每 token 读的 KV 继续缩小（[[A1 KV 状态变小之后]]），decode 瓶颈更集中在权重读取，SRAM 容量能否装下权重切片成为关键。
- **规模小**：1024 卡超节点、9,600 芯片 pod 的优势只在需要大 EP / 大 TP 的模型上体现。
- **主机内存成为状态层**：Engram 表（180+ GiB）、SWA 池（主机 DRAM 的 10%）、KV 卸载都压在 CPU 内存上（[[A11 条件记忆 Engram]]）；LPX 机架配 12 TB DDR5、Vera CPU 与 GPU 之间的 C2C 带宽，都会从"配角"变成容量规划的主项——这一点讲座在 CPU/C2C 一节已有预感（1:50:47）。
- **故障爆炸半径**：72 卡乃至 1024 卡的 scale-up 域里一张坏卡影响整个域，备件必须按机架规划（[[A8 万卡故障与 goodput#2.3 规模本身改变了"备件"的单位]]）。
