# 追踪方法：每周查什么、怎样发现陌生项目、何时改正文

这些选择来自本轮发现：**最重要的变化先出现在 release notes 和模型报告里，论文往往滞后或只给原型**；而厂商数字常常没有条件。

## 每周（约 1 小时）

| 查 | 为什么 | 看什么 |
|---|---|---|
| vLLM / SGLang release notes | 新模型结构的支持最先落在这里（Engram、DSA、SWA 前缀复用、MegaMoE 都是在 release 里先看到） | "Breaking changes"、新 KV/state 类型、EP/确定性项、移除的功能 |
| Dynamo、llm-d、Mooncake release | 分层 KV、路由、PD 拓扑的生产化 | 新 connector、新存储层、路由策略 |
| DeepGEMM / DeepEP README 新闻 | 无 tag，只能看 README 新闻与提交 | 新融合 kernel、新硬件后端 |
| arXiv cs.DC + cs.LG 中含 serving/RL/FP4/KV 的新稿 | 原型与测量 | 先看测量条件段（硬件、模型、引擎版本、基线） |
| 引擎的 RFC 标签议题（如 vLLM RFC #48305） | 下一季度会落地什么 | 勾选进度 |
| **recipes.vllm.ai 与 NeMo AutoModel 的 model coverage 页**（第二轮新增） | 新模型的**部署形态**（表放哪、开哪些 flag、最低显存）最先写在这里，比技术报告更具体；第二轮的 Engram 更正就是从这里来的 | 新模型条目；`--engram-config`、KV offload、并行配置 |
| **MLPerf Endpoints 滚动提交、InferenceX 新配置**（第二轮新增） | 少有的公开、可拆开的服务端测量 | 并发、TTFT、交互度、功率是否同时给出；"初步"还是"已核验" |

## 每月

- 新旗舰模型报告（DeepSeek、Kimi、Qwen、GLM、MiniMax、Nemotron）：先读"基础设施"和"推理部署"两节——DeepSeek-V4 一份报告就改了本笔记 6 篇。
- 会议录取列表（OSDI/SOSP/MLSys/EuroSys/NSDI/ASPLOS）：按标题筛，再挑 2–3 篇读测量段。
- 厂商季度活动（GTC、Hot Chips、Cloud Next、WAIC、OCP）：只记"押注了什么 workload"，数字进台账标【厂商声明】。
- 财报新闻稿：只看产品是否被提及（第二轮：CPX/LPX/CMX 在 Q3 FY27 新闻稿中均未出现）。
- MLPerf 每半年一轮（Training 约 6 月 / 11 月，Inference 约 4 月 / 9 月）：先读 MLCommons 新闻稿（新基准、精度说明），再读提交者补充讨论，最后才看厂商博客。

## 怎样发现陌生项目

本轮的陌生项目（PrfaaS、DORA、DETENT、Kthena、RBG、FastAFD、TensorHub）几乎都是从下面三条路找到的：

0. **从部署文档的 flag 反查**（第二轮新增）：vLLM v0.34.0 的 `disk_offload` 条目指向 Qwen3.8 的 PLE 表，再反查到 SlackTier。
1. **从 release notes 的依赖与集成反查**：Dynamo 的 backend pin、llm-d 的组件 pin、Miles 的集成列表（Harbor、NeMo Gym、OpenEnv…）。
2. **从机制词而非项目名搜索**，中英各一次：如"KV 跨数据中心"、"批不变 RL rollout"、"attention FFN 分离"、"超节点 PD 分离 生产"。
3. **从中文生产/社区报告**（InfoQ、厂商云社区、知乎技术专栏）找部署侧项目——这些通常不出现在英文论文里。

## 何时改正文

| 证据 | 动作 |
|---|---|
| 一手 release 中出现【已发布】功能，改变了某篇的"代价"或"反转条件" | 改正文，在该段加日期 |
| 只有论文/原型 | 放入该篇"未解决"或作为【原型】段落，不改结论 |
| 只有厂商声明、无条件 | 进台账；正文只描述"押注方向" |
| 独立复现与作者数字冲突 | 改正文，保留两组数字与条件 |
| 二手报道（撤回、重新设计） | 标"二手/未证实"，直到一手确认 |
| 某反转条件被实测验证或推翻 | 同时改专题与 [[T3 结论反转条件]] |

每次修改在 [[变化记录]] 追加一行，并更新 [[02 进度与覆盖索引]] 的核对日期。

## 如何把每周新发现并入本版（第二版新增）

本版的结构是"判断 → 机制 → 代价 → 反转条件"。每周研究不需要新开文件，按下面的顺序决定放哪：

1. **它改变了哪一个判断？** 能对应到 A1–A14 的某一章 ⇒ 放进那一章，位置按它影响的是"workload / 机制 / 代价 / 反转条件"哪一段。对应不到任何一章，且一手证据足以支撑一个新判断 ⇒ 才新开一章，并更新 [[01 组织说明#第二版的结构变化（以及为什么）]]。
2. **它推翻了旧段落的结论吗？** 是 ⇒ 原位改写 + 文首加"对第 N 轮的更正"警告框 + 在 [[变化记录#第二轮的更正]] 同类表里记一行。否 ⇒ 直接并入论证，不加警告框。
3. **它属于哪条线索？** 新状态类型 ⇒ [[T1 状态的生命周期]] 加一行；新的"省下/新增" ⇒ [[T2 代价搬家账本]]；新的反转条件 ⇒ [[T3 结论反转条件]]。
4. **台账与索引**：新来源进 [[来源台账]]（类型、首发、版本、阅读深度）；如果它关闭了 [[02 进度与覆盖索引#3. 剩余研究限制，以及为什么留作未来问题]] 中的某一条，划掉并写明在哪一章用到。
5. **可复算**：如果新数字能和已有算例放在同一把尺子上（如每 token 字节、每步 kernel 数、每 kW 吞吐），更新算例，而不是只加一个孤立数字。

**每周的最小优先级**：先查 [[02 进度与覆盖索引]] 第 3 节的 12 个开放问题各自的"下一步来源"——这些是已知能改变正文的地方；再做一次不预设项目名的发现搜索。
