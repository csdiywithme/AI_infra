# 变化记录：过去一年哪些判断被改写

以 HPCGame 讲座（2026-01-28）与 2025 年末的常见理解为基线。只记**改变系统设计/运维/评估方式**的变化。

## 变得更重要

| 问题 | 之前 | 现在 | 主要证据 | 专题 |
|---|---|---|---|---|
| 状态的异构管理 | KV 同质、paged block | 压缩 KV + 每请求固定状态 + 递归状态并存；paged attention 不兼容 | DeepSeek-V4 §3.5；PrfaaS §3.2 | [[A1 KV 状态变小之后]] |
| KV 跨机房 / 落盘 | 必须同 RDMA fabric | hybrid 模型 Φ_kv 降约一个数量级，普通以太网可承载长请求 | PrfaaS Table 3、§4 | [[A1 KV 状态变小之后]] |
| 会话级调度 | 请求级 | agent 负载命中 84.6–99.5%、decode 占 91–98.6%；KV TTL | 2605.26297；Continuum | [[A2 Agent 负载]] |
| 训推数值一致性 | 调试选项 | RL 正确性条件；引擎伞形 RFC；旗舰模型报告单列 | vLLM RFC #48305；DETENT；DeepSeek-V4 §3.3 | [[A6 数值一致性]] |
| RL 系统工程 | 同步、全量广播 | 异步多版本、P2P/增量权重、沙箱一等资源 | Miles v0.1；DORA；ProRL Agent | [[A7 RL 后训练系统]] |
| goodput 与容错 | 运维话题 | 10 万卡每 18 分钟一次故障；硬件宣传以 goodput 为指标 | FT-HSDP；TPU 8t | [[A8 万卡故障与 goodput]] |
| 静默数据损坏（SDC） | 偶发硬件问题 | 3,500 万 GPU 小时中 18 次、多数不触发 NaN；压力测试漏检 >60%；需要逐位确定训练来定位 | AEGIS、SDCHunter（OSDI '26） | [[A8 万卡故障与 goodput]] |
| 主机 DRAM 作为状态层 | KV 的溢出区 | Engram 表 180+ GiB、SWA 池占 10%、KV 卸载三方争用 | V4.1 报告；SlackTier | [[A11 条件记忆 Engram]] |
| kernel 正确性验证 | 测试问题 | AI 生成 kernel 声称 1.43× 在验证后为 0.88× | KernelBench-Verified | [[A10 Kernel 语言与编译栈]] |
| 功率平滑 | 机房工程 | 单机房几十 MW 秒级摆动；GPU 固件、机架储能、软件共同承担；地板约 +10.5% 能耗（模拟） | 2508.14318；GB300 电源架 | [[A14 电力与成本]] |
| 公开的服务端基准 | 厂商自报 | MLPerf Endpoints（按并发扫 Pareto，滚动提交）、InferenceX（开源、真实硬件） | MLCommons；SemiAnalysis | [[A14 电力与成本]] |

## 第二轮的更正

| 第一轮说法 | 新证据 | 现在的说法 | 在哪改 |
|---|---|---|---|
| vLLM 把 Engram 表放在对端 HBM，暗示生产延迟预算更紧 | v0.33.0 该条目是 GPU 常驻模式下 GB200 DEP 卡死的修复；官方配方默认 `cpu_offload`（主机 DRAM） | 默认主机 DRAM；能否下沉到 SSD 取决于表在第几层（截止时间），不是 batch | [[A11 条件记忆 Engram]] |
| Engram 的反转条件是"大 batch 时 PCIe 不够" | batch 128 每层每步约 0.8 MB，带宽远够；约束是第 1 层约 0.3 ms 的遮掩窗口 | 反转条件是"早层 + 慢介质"，以及与 KV 争用 DRAM | [[A11 条件记忆 Engram]]、[[T3 结论反转条件]] |
| "本轮读到的 V4 报告未提及 Engram，需核对 V4.1 模型卡" | V4.1 报告与部署文档明确 Engram 在第 1、14 层 | Engram 属于 V4.1，不属于 V4 的可读部分 | [[A11 条件记忆 Engram]] |
| 旧笔记引用 TE NVFP4 页的 B300 2.03× / 3.55× | 官方页面全文无任何加速数字 | 不采用该数字 | [[A5 FP4 进入训练]] |
| A8 的核心是"副本级容错" | SDC、hang、fail-slow 的生产数据 | 有效时间由频率 × 发现时间 × 恢复粒度共同决定；副本级容错只解决最后一项 | [[A8 万卡故障与 goodput]] |
| T1 判据第一项"能提前多久知道要它" | SlackTier 的分层窗口测量 | 改为"离被使用还有多少计算可以遮掩"，并加"和谁抢容量" | [[T1 状态的生命周期]] |

## 值得新位置的新兴问题

- 生成 kernel 的**正确性验证**（SOSP 2026：M2K、Ave）。
- **语音等实时会话**的上下文编排（SOSP 2026 标题）。
- KV 作为"临时、派生、可重算"数据的**存储语义**（去副本、去元数据）。
- 跨机房 KV 的安全/多租户边界（尚无公开讨论）。
- **截止时间感知的参数放置**：Engram / PLE 表按"第几层被读"决定介质（SlackTier）——可能推广到其他只读、可预知的状态。
- **沙箱机群**与 GPU 机群同量级（V4.1：数百万并发沙箱、单节点 2,500 容器）。
- **训练的去同步化**同时影响容错、功率和流水线气泡，但尚无统一量化。
- **投机解码方法更替**：vLLM v0.33.0 移除 Medusa/MLP speculator，加入块扩散 drafter 的 XPress 精修与 FLy 有损验证；LPX 据报道支持外部 drafter——仍只在 release notes 层面，未成章。
