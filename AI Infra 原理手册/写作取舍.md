# 写作取舍

这份说明写给项目负责人：我把这一版写成现在这个样子，每个选择是什么，理由是什么，代价是什么。每条都指向正文里实际体现它的位置，方便你对照已发布版（`proposal/完整候选稿/`）检查。

## 1 先放什么：一个对象，而不是一个领域

已发布版有十六篇主题文章，按领域划分，开头是“当前判断”，结尾是“路线一览”“近期变化”“开放问题”。它的问题不在于某一篇写得不好，而在于很多判断要跨两三个领域才能做出，而领域划分恰好把它们拆开了。

最清楚的例子是 11-23 这一期。稀疏注意力的索引成本在已发布版里写在《模型结构与数值表示》，TableTune 的成本表写在《投机解码》，CUDA Graph 覆盖写在《编译、DSL 与自动调优》。三处各自都对，但读者要自己把三篇拼起来，才会发现它们说的是同一件事：投机解码用来选候选长度的那张成本表，有两种独立的过期方式。

所以这一版每篇跟踪一个具体对象。一个领域的内容放在这个对象经过它的那一段：

- [一轮生成](<文章/01 一轮生成.md>) 跟着一轮投机 decode 走。稀疏注意力的索引器写在这篇的 [§5](<文章/01 一轮生成.md#5 稀疏注意力把索引成本放进验证行>)，因为它的成本正是在这里付的：每一行验证都要过一次索引器。结构本身的选择（GQA、窗口、递归）留在 [历史状态 §2](<文章/02 历史状态.md#2 共享表示、删除连接、压缩成状态>)，因为那里讨论的是历史保存成什么。
- 每篇开头一段说明跟踪的对象，接着是一个“读完这篇，你应该能判断”的框，然后才进入机制。比如 [一轮生成](<文章/01 一轮生成.md>) 开头第二段就说明全篇分三部分（接受规则、多行前向、成本表），以及为什么把篇幅压在第三部分。

**代价。** 想通读“投机解码领域的全部材料”的读者，得不到一篇按领域收齐的文章。我的判断是，这类需求由每篇末尾的“证据”表和入口页的问题表满足就够了。已发布版的领域文章也都还在。

## 2 合并了什么，各自的理由

十六个领域合并成十篇，外加一篇方法短文。每次合并都基于同一个标准：两个领域是否共用一条机制，以至于分开写必须各讲一遍。

| 合并 | 共用的机制 | 正文里体现在哪 |
| --- | --- | --- |
| 投机解码 + 稀疏注意力的索引成本 | 同一张验证成本表 | [一轮生成 §3–§5](<文章/01 一轮生成.md#3 每个已提交 token 花了多少时间>) |
| 模型结构（注意力、递归）+ KV 与状态系统 | 历史保存成什么，决定系统怎样共享、搬移、回收它 | [历史状态 §2](<文章/02 历史状态.md#2 共享表示、删除连接、压缩成状态>) 接着就是 [§3 共享前缀](<文章/02 历史状态.md#3 两条请求共用一段前缀>) |
| 通信与互联 + 存储与异构内存 | 同一套“提交—可见—可复用—消费结束”交接协议，同一种关键路径计算 | [数据移动 §3](<文章/04 数据移动.md#3 交接完成有四个时刻>) 先讲协议，§6 直达存储时直接复用 |
| 算子与 GPU 执行 + 编译、DSL 与自动调优 | 编译器决定的正是算子的布局、同步和命中路径 | [算子与编译 §6](<文章/05 算子与编译.md#6 编译保存的是代码和它的成立条件>) |
| 低精度数值 + 硬件与跨平台 | “一个数多少字节、在什么单元上算”同时决定了量化收益和硬件选择 | [数值与硬件 §1](<文章/06 数值与硬件.md#1 “4 bit”展开成字节>) 到 [§4](<文章/06 数值与硬件.md#4 算力、带宽、容量各缩短哪段>) |
| 训练数据与配方 + 分布式训练 + MoE 并行 | 同一次参数更新：样本身份、损失分母、状态所有权、恢复边界 | [训练一次更新 §4](<文章/07 训练一次更新.md#4 装满设备，同时保持学习目标>) 的全局分母，直接接到 §5 的分片 |
| 多模态 / Agent / 流式 + 检索推荐 | 模型之外的阶段：输入怎样变成工作，输出怎样变成已发生的事实 | [模型之外的任务 §4](<文章/09 模型之外的任务.md#4 打断以后，什么还算发生过>)、[§7](<文章/09 模型之外的任务.md#7 候选集合决定下游能看见什么>) |
| 集群资源与可靠性 + 交付与模型生命周期 | “资源何时真的可用”和“组合何时真的可服务”是同一类判断 | [持续交付 §2](<文章/10 持续交付.md#2 资源何时真的可用>) 与 [§6](<文章/10 持续交付.md#6 ready 之前还有什么>) |

《模型结构与数值表示》是唯一被拆开的领域：注意力和递归进了 [历史状态](<文章/02 历史状态.md>)，量化和低精度训练进了 [数值与硬件](<文章/06 数值与硬件.md>)，MoE 进了 [训练一次更新 §7](<文章/07 训练一次更新.md#7 专家：平均负载失去预测力>)。“模型结构”本身不是一种系统成本；它通过改变历史、数和专家分布，在三个不同的地方产生成本。按成本落在哪里拆开，读者才能把结构选择和它的系统后果放在同一页上读。

五篇分析工具短文合并成了一篇 [五笔账](<文章/00 五笔账.md>)。它们各自篇幅很短，放在一起读更容易看出：关键路径、容量账、提交点、分母、证据层次是一套算法的五个部分，各篇文章反复调用的就是它们。

## 3 删去或压缩了什么

**删去，因为它们服务的是维护过程，不是读者：**

- 每篇末尾的“近期变化”日期列表。已发布版的《KV 与模型状态》末尾有四条带日期的条目。这一版每篇末尾只留一行“最近改写”，指向改写它的那一期进展和那一节，例如 [一轮生成末尾](<文章/01 一轮生成.md#证据>)。文章要整节改写，不能靠追加条目来更新。
- frontmatter 里的证据清单。证据改为每篇末尾的“证据”表，一行一个判断，写明标记和证据卡。读者从判断出发查证据，而不是从卡号出发找判断。见 [一轮生成 · 证据](<文章/01 一轮生成.md#证据>)。
- “路线一览”表。它按“条件 → 倾向做法 → 主要代价”排列，读起来像推荐清单。这一版换成“结论在什么时候反过来”，按“你原本的判断 → 什么条件下反过来 → 先查什么”排列，见 [一轮生成 §8](<文章/01 一轮生成.md#8 结论在什么时候反过来>)。这样写把拐点放在前面，而拐点正是这套笔记最想教会的东西。
- “开放问题”列表。开放问题如果是正文论证的一部分，就写进对应那一节（例如 [一轮生成 §5](<文章/01 一轮生成.md#5 稀疏注意力把索引成本放进验证行>) 末尾说明“融合索引在验证行上能省多少目前没有实测”）；如果只是研究方向，就进候选队列。

**压缩，因为它们是配置或发布状态，不是机制：** Kueue 的发布说明、AWS 托管 MLflow 同步、CUDA 13.5 的 Tile 互操作发布状态、AITER 的 CI 调整、Intel GPU D-series 的容量数字、UE 1.1 规范公告。这些在已发布版里各占一段，这一版各压成一两句，或只留在证据表里。证据卡没有删任何一张。完整清单在 [status](<status.md#压缩或略去的材料>)。

**保留不动：** 主要的教学算例。A/B/C 分布、2.02 与 0.91、1088→576 MiB、42.95 ms、$0.99^{100}$、77 分钟恢复时间线、24 ms 的 NPU 分区，这些是这套笔记最有价值的部分，保留下来的算例没有改任何一个数字。少数次要算例（例如 $128\times128$ 矩阵乘的 96 KiB 输入输出账）被略去，清单同样在 status 里。

## 4 新写了什么

这一版不只是重新排列。下面几处是我新写的推导或连接，已发布版里没有：

- **索引字节账。** [一轮生成 §5](<文章/01 一轮生成.md#5 稀疏注意力把索引成本放进验证行>) 用一组标为【算例】的数说明：稀疏以后，索引器每行读 16 MiB，核心注意力只读 8 MiB；5 行验证能否共享索引读取，决定是 16 MiB 还是 80 MiB。已发布版只用文字说“索引器仍可能扫描长历史”，这组数让读者可以自己判断“共享得了 / 共享不了”的差距有多大。
- **成本表的两种过期方式。** 已发布版把 TableTune 和稀疏索引分别列为两条近期变化。这一版把它们写成同一个结论的两个原因，见 [一轮生成 §4](<文章/01 一轮生成.md#4 成本表从哪里来，又怎样过期>) 与 §5，以及 [进展 §1](<进展/2026-11-23.md#1 投机解码的成本表会过期>)。我在文中明确写了：“沿用不含索引项的成本表会低估长候选的代价”是从成本结构推出的方向，没有实测。
- **跨篇的五条链。** 已发布版有单独的《跨领域因果链》页。这一版把它压进 [入口页](<00 从这里开始.md#沿一条跨篇的链进来>)，每一环都链接到具体某一节，而不是某一篇。同时每篇正文在机制交汇的那一句当场链出去，例如 [一轮生成 §3](<文章/01 一轮生成.md#3 每个已提交 token 花了多少时间>) 讲到“验证行增加了矩阵的 $M$”时，直接链到 [算子与编译 §1](<文章/05 算子与编译.md#1 形状决定先省哪一笔>)。

## 5 证据怎样标

保留已发布版的四个标记：【已核】【作者数据】【独立】【候选】。它们对应的就是你要求保留的区分：机制已验证、作者报告的结果、线索。【候选】只出现在进展的“待核”里，不进入文章论证。

新增一个标记【算例】，标在教学数字出现的地方。已发布版在文末写一句“算例为自写推导”，读者读到 0.91 时并不知道它是假设还是实测。现在 [一轮生成 §3](<文章/01 一轮生成.md#3 每个已提交 token 花了多少时间>) 的两组耗时数字当场标【算例】，而紧接着的《Performance or Illusion?》实测标【作者数据】。读者可以清楚看到哪个数是讲道理用的，哪个数是有人量出来的。

作者数据只在说明机制或拐点时引用，而且同一句写出关键条件。例如 [进展 §1](<进展/2026-11-23.md#1 投机解码的成本表会过期>) 写 TableTune 时，同一段说明了 goodput 指的是输出 token/s，不是 SLO 合规率。

反例用 `> [!warning] 反例` 框单独标出，例如 [一轮生成 §1](<文章/01 一轮生成.md#1 为什么拒绝之后仍是原分布>) 的 argmax 反例和 §3 的 0.91。已发布版里反例常常混在一段的中间，读者容易把它读成限定语。反例是这套笔记的论证主体，应该放在显眼的位置。

## 6 没有重写的部分

**基础章节 00–09。** 已发布版的 [基础](<基础/01 我们究竟在优化什么.md>) 用一个 8B 代码助手从矩阵乘法讲到集群，教学连贯，这一版的文章都把它们当作前提引用。重写它们会消耗大量篇幅，换来的改进很小，所以没有重写。

**证据卡、研究记录、候选队列。** 这些是研究层，按要求原样保留。新版文章用相对链接指向已发布版的 [来源与证据](<研究台账/来源与证据.md>)，没有复制，也没有改写。

**专题研究《Agent 算子开发与优化》。** 它是一份带日期的完整档案，入口页写得好，已发布版也保留未动。这一版在 [算子与编译](<文章/05 算子与编译.md>) 里引用它。

## 7 进展怎样写

已发布版的 11-23 进展按三个主题平铺，每条“之前 / 现在”。这一版做了四处改动：

1. **一项判断，一个故事。** TableTune 和稀疏索引合成第 1 条，因为它们改变的是同一个判断；见 [进展 §1](<进展/2026-11-23.md#1 投机解码的成本表会过期>)。导语第一句就说“这一期只有一项判断变了”，读者读完导语就知道这一期的分量。
2. **每条加一段“你现在能判断的”。** 写成读者下次看到类似说法时要问的三个问题，例如 [进展 §2](<进展/2026-11-23.md#2 存储直达 GPU：省下一次复制，接过三项责任>) 末尾的四个问题。这样一条进展就成了一件可以带走的工具，而不只是一条消息。
3. **状态变化和判断变化分开。** TitanRL、Uranus、llm-d 放在 [§3](<进展/2026-11-23.md#3 状态变化：对正在用这些系统的人有用>)，标题直接说明它们只对正在用这些系统的人有用。待核按可能影响排序，Qwen4-Max 第一位，并写明它若成立会影响哪两篇。
4. **漏跑的那一周写给读者看。** 已发布版里，“11-16 没有完成记录”只出现在研究记录的表格前言里。这一版放在进展的第一行（覆盖范围）和最后一行（运行情况）。覆盖窗口变了，读者需要知道。

## 8 读者现在能推出什么

这一版组织方式的目标，是让读者可以自己回答已发布版里没有直接写出的问题。三个例子：

- **“某个稀疏注意力模型上，投机解码的最佳候选长度应该比稠密模型长还是短？”** 读者从 [一轮生成 §3](<文章/01 一轮生成.md#3 每个已提交 token 花了多少时间>) 的公式出发，在 §5 找到验证成本新增的索引项，再看它能不能在验证行之间共享，就能推出：共享不了时应该更短，共享得了时影响很小。还能推出要查的证据是什么：decode 验证路径上的实测，而现在没有这份数据。
- **“主存加大以后，KV 多副本还有用吗？”** [数据移动 §7](<文章/04 数据移动.md#7 小请求、尾部和副本的写入账>) 的 KVStream 反例（TTFT 加速比从 1.71 降到 0.98），加上 [历史状态 §5](<文章/02 历史状态.md#5 放到 GPU 外：取回还是重算>) 的“取回还是重算”公式，读者可以推出：主存装得下复用集以后，磁盘层能省的读变少，复制写入却一直在发生。
- **“P/D 分离的服务做滚动升级，为什么要预留额外的卡？”** [请求调度 §4](<文章/03 请求调度.md#4 同样四张卡，要不要拆阶段>) 说明拆池以后角色不能互借，[持续交付 §2](<文章/10 持续交付.md#2 资源何时真的可用>) 说明只有一个 prefill 时“先停旧的”会切断服务链，两处合起来就是 llm-d 那条修复的道理。

## 9 和已发布版对照时可以看哪里

- 同一条材料两种写法：已发布版《投机解码》第 5 节 vs [一轮生成 §4–§5](<文章/01 一轮生成.md#4 成本表从哪里来，又怎样过期>)。
- 同一期进展两种写法：已发布版《2026-11-23 进展》vs [本版进展](<进展/2026-11-23.md>)。
- 同一个入口两种写法：已发布版《从这里开始》按问题、主题、工具、基础四种方式排列 vs [本版入口](<00 从这里开始.md>) 按问题、对象、跨篇链、最近变化排列。
