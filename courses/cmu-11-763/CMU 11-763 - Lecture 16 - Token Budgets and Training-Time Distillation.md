> [!abstract] 本讲一句话

## 1. 效率单元改变了优化问题

前面的课反复问：如果允许多花推理预算，怎样得到更好的输出？
方法包括多次采样、重排序、MBR、反思、搜索和长链推理。
本讲从另一侧问：如果已经知道一种较好的行为，是否必须在每次服务请求中重新付出全部成本？

课件第 3 页明确把本讲定位为效率单元的转折。
它不是否认 test-time scaling，而是把质量与服务成本一起纳入目标。

以下约束形式是本文对主线的数学整理：

$$
\min_{\text{system}}\ \mathbb E[C(x)]
\quad\text{s.t.}\quad
\mathbb E[U(x,y)]\ge U_{\min}.
$$

$C$ 可以是金额、GPU 时间或延迟；$U$ 是任务效用。
实际应用还可能约束尾延迟、峰值显存和失败率，因此不一定存在一个统一标量成本。

课件第 8 页给出三条路线：

1. 从更强、更贵的模型蒸馏到便宜模型。
2. 把昂贵推理算法产生的优质输出蒸馏进模型。
3. 通过训练或推理控制缩短 reasoning chain。

前两条主要把在线成本转移到离线；第三条直接减少每次生成的工作量。
三者可以组合，但组合后仍需重新测量，而不是相加各论文的加速比。

## 2. Token 预算：首先把所有参与者记进账本

### 2.1 课件的四组符号

第 5 页使用：

- $T$：基础模型的 token 数。
- $N$：参与推理的序列数量。
- $S$：每条序列的步骤数量。
- $C$：外部模型或模块的计算成本。

为什么要单列 $C$？
因为生成 16 个候选后交给另一个 LM 打分，并不等于只生成了 16 个候选。
打分模型还要读取输入、读取候选，甚至输出自己的评估文本。

只统计最终返回用户的答案长度，会漏掉搜索、失败分支、批评与重写的主要成本。

### 2.2 单次采样与 Best-of-N

设输入长 $I$，每个候选平均输出长 $L$，采样数为 $N$。
先忽略缓存、批处理与提前停止，则：

$$
T_{\text{in,naive}}=NI,
\qquad
T_{\text{out}}\approx NL.
$$

若每个候选还需独立评分，外部成本约为 $NC_s$。
当 scorer 也是 LM 时，$C_s$ 不能只数它最后输出的一位分数。
它处理候选全文的 prefill 也消耗资源。

若多个候选共享完全相同的 prompt 前缀，输入处理可能通过 KV 复用而减少。
但 $NL$ 个候选输出仍然需要生成；缓存不能把不同后缀自动变成同一段计算。

### 2.3 MBR、搜索与 refinement

以下是按课件第 5 页分类得到的量级分析，不是所有实现的精确 FLOPs：

| 方法 | 主要新增工作 | 易漏记的成本 |
| --- | --- | --- |
| Self-consistency | 多个候选，再提取答案与计票 | 不能解析的答案、未完成候选 |
| Reward reranking | 每个候选调用 scorer | scorer 的输入处理、额外解释 |
| MBR | 候选和伪参考之间计算 utility | 常见朴素实现的两两比较 |
| Step-level search | 每层保留与扩展多个前缀 | 被剪枝分支、lookahead、重复前缀 |
| Self-refine | 生成、批评、重新生成 | 旧答案与反馈在后续轮次中再次作为输入 |

MBR 有 $N$ 个候选、$M$ 个伪参考时，朴素评分量为 $NM$ 次 utility 计算。
当同一组样本兼任二者时，常写为 $O(N^2)$。
这不是所有优化 MBR 的下界；缓存表示、剪枝和近似算法可以改变实际代价。

Refinement 的串行轮次尤其重要。
即使每轮只返回短答案，模型也可能反复读取累计增长的历史。
若完全保留此前全部答案与批评，累计输入 token 的增长可能快于轮数线性增长。

## 3. Token 数、金额与延迟不是同一个量

### 3.1 第 6–7 页的成本分层

课件提醒：顺序生成和并行生成不同，搜索和采样不同，lookahead/rescorer 会增加额外信息，单个 token 的计算量也可以改变。
第 7 页进一步区分 input、output 与可精确复用的 input。

例如 8 条各 100 token 的并行候选，与一条 800 token 的连续推理，输出总数相同。
前者有批处理机会，后者具有更长的串行依赖。
但前者同时保存多个后缀的 KV cache，也可能受到显存、并发额度或批处理效率限制。

因此不能从“token 减半”直接推出“延迟减半”。
也不能从“并行生成很快”推出“总 GPU 成本很低”。

### 3.2 一个更完整的服务账本

下面是工程补充的计费模型：

$$
\text{Cost}
=c_{\rm in}T_{\rm in,uncached}
+c_{\rm cached}T_{\rm in,cached}
+c_{\rm out}T_{\rm out}
+C_{\rm tools}+C_{\rm judge}.
$$

所有单价必须使用同一计量单位。
若服务商按百万 token 报价，需要最后除以 $10^6$。
本讲课件出现的历史价目截图只用于说明输入/输出/缓存价格不同，不用于给出今天的 API 预算。

本地部署则还应记录 GPU 秒、batch size、利用率、显存与请求排队时间。
相同 token 数在不同模型尺寸、上下文长度和 serving 实现下，成本可能明显不同。

### 3.3 延迟看关键路径

对于候选并行生成再评分的系统，粗略可以写成：

$$
T_{\rm wall}
\approx T_{\rm queue}
+\max_i T_{\rm generate,i}
+T_{\rm score}
+T_{\rm select}.
$$

这是理想化并行公式：实际并发限制可能让候选分成多批。
最长候选还会造成 straggler，推高请求尾延迟。
长度控制不仅减少平均 token，也可能改变 P95/P99 延迟。

## 4. 输出蒸馏：把教师行为变成学生监督数据

### 4.1 第 9–10 页的基本情形

教师 $P$ 强而贵；学生 $Q$ 便宜但弱。
可以给教师更好的提示、更多上下文或更充分的计算，让它为大量输入生成训练输出。
学生通过微调学习这些输出，在部署时使用更便宜的生成方式。

第 10 页的图不只是“大模型教小模型”：教师端有丰富的 prompt 与任务信息，学生端可以只接收简短任务指令。
这提示我们，蒸馏对象可以包含 prompt engineering 带来的行为改进。

### 4.2 序列级蒸馏的 NLL

以下公式是对课件 finetuning 图的标准展开。
教师系统为输入 $x$ 产生筛选后的目标 $\hat y$，训练：

$$
\mathcal L_{\rm seq}
=-\sum_{(x,\hat y)\in D}
\sum_{t=1}^{|\hat y|}
\log Q_\theta(\hat y_t\mid x,\hat y_{<t}).
$$

学生看到的是目标 token，而不是教师完整的词表概率分布。
这通常适用于只能调用黑盒教师 API 的情况。

一个重要区别：

- 从教师分布独立采样多个标签，近似学习教师的输出分布。
- 从大量候选中只保留最好标签，学习的是**选择算法诱导的分布**。

后者可以比教师的普通 greedy 输出更好，也可能更窄、更受 evaluator 偏好影响。
因此实验必须记录“标签怎样产生”，不能只记录教师模型名称。

### 4.3 蒸馏不会自动洗掉教师错误

若教师系统偏爱冗长答案，学生可能继承冗长风格。
若教师把某类事实答错，NLL 会提高学生复现错误答案的概率。
数据规模增大并不等于错误被平均消除，系统性偏差可能被强化。

对部署任务，应保留独立验证集、领域覆盖与错误类别分析。
这是工程建议，不是课件展示了某个通用过滤器。

## 5. Logits 与表示蒸馏：监督信号可以更细

### 5.1 Token-level KL

第 11–12 页展示教师/学生 logits 对齐和 KL 方向。
设相同上下文 $h$ 下的教师、学生词表分布为 $P(\cdot\mid h)$、$Q_\theta(\cdot\mid h)$。
常见蒸馏目标为：

$$
\mathcal L_{\rm forward}
=\mathbb E_{h\sim\mu}
\left[D_{\rm KL}\big(P(\cdot\mid h)\Vert Q_\theta(\cdot\mid h)\big)\right].
$$

其中 $\mu$ 是训练时使用的上下文分布。
选择教师轨迹、真实数据轨迹或学生生成轨迹，会影响学生在哪些状态上学会模仿。
仅写一个 KL 名称并没有完整定义训练算法。

将 KL 展开：

$$
D_{\rm KL}(P\Vert Q)
=\underbrace{\sum_v P(v)\log P(v)}_{\text{对学生参数为常数}}
-\sum_v P(v)\log Q(v).
$$

因此优化学生时，forward KL 等价于最小化教师软标签交叉熵。
它让“非最高概率但仍合理”的 token 也提供监督，而单个硬标签只直接指定一个目标。

### 5.2 温度不是无关实现细节

可用温度 $\tau$ 将 logits 变成软分布：

$$
P_\tau(v)=\frac{\exp(z^P_v/\tau)}{\sum_u\exp(z^P_u/\tau)}.
$$

学生也使用相同温度，常见实现将 KL 项乘以 $\tau^2$ 以补偿梯度尺度变化。
这是标准实现补充，不是课件要求所有蒸馏必须采用该系数。
温度更高会使分布更平滑，但不自动提升蒸馏效果。

此外，直接对齐 logits 通常需要兼容的词表和 token 位置。
教师与学生 tokenizer 不同，不能把两个不同含义的词表索引机械计算 KL。
序列级蒸馏则更容易跨 tokenizer 使用文本目标。

### 5.3 Forward KL 与 reverse KL 的图该怎样读

第 12 页用多峰 $P$ 和受限的单峰 $Q$ 展示：

- 最小化 $D_{\rm KL}(P\Vert Q)$ 倾向让 $Q$ 覆盖教师有质量的区域。
- 最小化 $D_{\rm KL}(Q\Vert P)$ 倾向避开教师概率很低的区域，可能集中到其中一个峰。

这是 mode-covering / mode-seeking 的经典直觉。
它不是“forward KL 必然平均化、reverse KL 必然丢峰”的无条件定理。
模型族、支持集、优化难度和上下文分布都会影响最终结果。
若学生足以准确表示教师，两个方向都可在 $Q=P$ 处取得零。

### 5.4 Hidden states 和 attention

第 13 页包含表示匹配示意与 TinyBERT 的 attention/hidden loss。
若学生更浅或 hidden dimension 不同，通常需要层映射和投影。
一个示意目标为：

$$
\mathcal L_{\rm hidden}
=\sum_\ell\left\|
W_\ell H^Q_\ell-H^P_{m(\ell)}
\right\|_F^2.
$$

$m(\ell)$ 指定学生层对应哪个教师层，$W_\ell$ 对齐维度。
也可以匹配 attention 分布或使用余弦相似度。
这些监督需要访问内部表示，因此与“只拿教师文本输出”的 API 蒸馏成本和权限条件不同。

## 6. 偏好与奖励也可以传递教师行为

第 14–15 页把 RLHF 和 DPO 放入蒸馏讨论。
教师不一定逐 token 教学生，还可以判断两个答案哪个更好，或提供 reward。

基于 reward 的优化让学生提高高分行为的概率；DPO 则直接使用 $(x,y^+,y^-)$ 偏好对。
下面是 [DPO 原论文](https://arxiv.org/abs/2305.18290)目标的标准写法，用于理解第 15 页图示：

$$
\mathcal L_{\rm DPO}
=-\mathbb E\log\sigma\left(
\beta\left[
\log\frac{Q_\theta(y^+\mid x)}{Q_{\rm ref}(y^+\mid x)}
-\log\frac{Q_\theta(y^-\mid x)}{Q_{\rm ref}(y^-\mid x)}
\right]\right).
$$

$Q_{\rm ref}$ 是参考策略；$\beta$ 控制相对参考的尺度。
这里的序列 log probability 是 token log probability 之和。
如果擅自换成长度平均值，就改变了目标，不能仍假定等价于原始公式。

DPO 不要求另训一个显式 reward model 再进行在线 RL。
但数据仍依赖某种偏好来源：人类、教师 judge、任务验证器，或本讲后半段的解码排序。

因此“没有显式 RM”不等于“没有监督偏差”。
第 16 页列出的适用场景包括：有比本地模型强的教师、缺人类标注预算、希望得到更小的本地模型。

## 7. 本讲最关键的替换：教师是系统，不必是大模型

第 17 页把原来的 “models $P,Q$” 改成 “systems”。
两个系统甚至可以使用同一个 base model。

例如：

```text
离线教师系统：同一 LM → 采样多个候选 → QE/MBR 选优
                                    ↓ 合成标签或偏好对
学生训练：                  NLL 或 DPO
                                    ↓
在线学生系统：更新后的 LM → greedy / 小 beam → 返回
```

教师的优势来自“模型 + 推理策略”，而不一定来自参数量。
这也解释了 self-distillation 为什么不构成逻辑矛盾：同一模型的昂贵搜索可以找出它普通解码很少返回的优质输出。

训练再提高这些输出的概率，让便宜解码更容易找到它们。
这里并没有从毫无质量信号的系统中凭空创造监督：选择器、utility 或偏好构造提供了额外归纳偏置。

## 8. Finkelstein：把 QE / MBR 的在线收益搬到训练时

### 8.1 第 18 页的机器翻译流程

任务是英语翻译到德语或日语。
常规路线先用平行语料训练，再用高质量数据微调，最后在测试时进行 MBR。
本讲考虑将昂贵解码产生的翻译用于微调，从而在测试时保留便宜解码。
研究来源是 [MBR and QE Finetuning](https://proceedings.iclr.cc/paper_files/paper/2024/hash/ae817e85f71ef86d5c9566598e185b89-Abstract-Conference.html)。

QE 与 MBR 的区别必须保留：

$$
\hat y_{\rm QE}=\arg\max_{y\in H}q(x,y),
$$

$$
\hat y_{\rm MBR}
=\arg\max_{y\in H}\frac1M\sum_{j=1}^M u(y,r_j;x),
\qquad r_j\sim P(\cdot\mid x).
$$

QE 直接评价源文本和候选；MBR 通过候选与伪参考之间的 utility 近似期望效用。
使用效用最大化的写法与最小期望风险等价，只是符号方向不同。

### 8.2 第 19 页：先固定输入集合比较标签来源

课件表格给出的该翻译实验 COMET20 分数：

| 模型或数据处理 | 测试结果 | 相对 base beam |
| --- | --- | --- |
| Base + beam | 57.79 | 基线 |
| Base + QE decoding | 59.21 | +1.42 |
| Base + MBR decoding | 59.35 | +1.56 |
| Beam 输出微调后 + beam | 57.08 | −0.71 |
| MBR 输出微调后 + beam | 58.02 | +0.23 |
| QE 输出微调后 + beam | 59.63 | +1.84 |
| 人类 reference 微调后 + beam | 60.95 | +3.16 |

最重要的观察不是“所有自训练都有用”。
直接使用 beam 输出微调在此表中变差；选择生成质量影响监督质量。
人工 reference 在这一阶段仍然最好，不能只展示合成数据成功的行。

这些是特定任务、模型与指标下的结果，不代表 COMET20 每增加一点都对应固定比例的人类质量提升。

### 8.3 第 20–21 页：合成数据突破人类标签数量限制

合成标签可以用于只有源语言输入、没有人类译文的数据。
因此第二阶段不再受制于原先的小规模标注集合。
第 20 页展示自生成数据带来进一步收益，例如从 reference-finetuned 模型出发，self-MBR 的结果为 61.49。

第 21 页加入更强的 PaLM-2 教师。
课件展示：以 reference-finetuned 为起点，教师 greedy、QE、MBR 标签对应的结果分别为 61.61、62.35、63.62。
它支持“更强教师 + 更好的标签选择”在此设置下效果更好的结论。

但不能将跨阶段的所有变化归因于某一个开关。
初始化、数据量、教师质量与选择方式都可能发生变化，比较时要明确控制变量。

### 8.4 第 22 页：蒸馏后再运行同一解码器还会提升吗

课件结论是：收益通常有限；有时换一种未在训练标签中使用的解码方法更有帮助。
例如第三阶段 MBR-finetuned 列中，beam 为 63.62，MBR 为 62.30，QE 为 63.05。
在这一列，额外解码成本没有带来更好的结果。

不能把这解释为“蒸馏在数学上完全等于运行 MBR”。
更谨慎的解释是，模型已吸收部分选择器偏好，重复同一种选择未必再提供互补信息。
过度集中、指标偏差和候选分布变化也值得检查；课件并未给出一种适用于所有场景的唯一原因。

## 9. Yang：不是只学冠军，也可以学习候选之间的偏好

### 9.1 第 23–24 页的偏好对构造

对候选进行 MBR 排序，得到 $y_{(1)},\ldots,y_{(N)}$，从好到坏排列。
可以采用：

| 策略 | 偏好对 | 直觉与风险 |
| --- | --- | --- |
| BW | best 对 worst | 差距大，监督清楚，但信息较少 |
| BMW | best 对 middle；middle 对 worst | 增加中间层次的信息 |
| CP | 相邻排名连续配对 | 细粒度多，但邻近候选差异可能很弱 |
| CPS | 跨固定步长配对 | 在数量和差距之间折中 |

课件第 24 页将 CP 解释为相邻连续配对，不应随意改写成全部 $\binom N2$ 个偏好对。
生成更多候选与产生更多可靠偏好信号不是一回事。

### 9.2 实验：更多、更细的偏好不一定更好

课件引用 [Yang 等的 DPO-MBR 翻译研究](https://arxiv.org/abs/2311.08380)。
第 24 页表格是 WMT21 Zh→En、BLOOMZ 的 BLEURT 结果：

| 配对策略 | 8 个候选 | 16 个候选 | 32 个候选 |
| --- | --- | --- | --- |
| BW | 63.3 | 63.9 | 63.9 |
| BMW | 63.9 | 64.2 | 63.6 |
| CP | 62.5 | 62.4 | 60.4 |
| CPS | 62.3 | 63.5 | 62.9 |

32 个候选没有使所有策略更好；CP 甚至更差。
一个合理但非唯一的解释是：utility 的微小差异容易含有噪声，强迫学生学习所有邻近次序可能放大这种噪声。
这属于对实验的分析，不是由表格单独证明的因果结论。

第 25 页进一步比较不同测试集与模型的解码/微调组合。
整体支持将 MBR 的一部分收益迁移到便宜解码，但不是每个语言方向和指标都完全匹配教师系统。

## 10. Wu：蒸馏推理策略也能用于 instruction following

第 26–29 页把相同思路扩展到开放式指令回答。
来源是 [Better Instruction-Following Through Minimum Bayes Risk](https://proceedings.iclr.cc/paper_files/paper/2025/hash/6756c9f0a1a7c6d1d10ab252f16524f2-Abstract-Conference.html)。

### 10.1 第 27 页：质量与吞吐可以同时改善

图中的 SFT + MBR 相比 SFT + greedy，胜率更高，但生成系统更慢。
经过迭代 DPO-MBR 自训练后，学生使用 greedy 可以达到接近 MBR 系统的胜率，同时回到更高吞吐区域。
右侧时间分解还显示，MBR 的成本不只来自候选生成，候选评价/解码选择本身也很重。

这里的收益属于“训练改变模型后，在新的运行点上评估”。
它不同于在保持模型分布完全不变的条件下加速采样。
蒸馏允许分布改变，代价是需要验证行为、泛化和遗忘情况。

### 10.2 第 28 页：不能把高分全部解释成答案更长

课件比较不同策略的平均回答长度，以 words 为单位，而不是 tokenizer token。
最长候选基线约 395 words；greedy 约 310；MBR-Prometheus 约 320。
这提示评估时需要检查 length bias，而不是只看胜率。

但两个方法平均长度接近，也不足以彻底排除 evaluator 的长度偏好。
更严谨的实验还可以按长度匹配、任务类别分层，并进行独立人工复核。

### 10.3 第 29 页：平均收益掩盖任务差异

图中 argumentation、recommendation、technical writing 等类别有不同幅度的收益。
math 和 other 并不呈现一致的正收益。
因此不能把开放式指令 benchmark 的平均提升，直接外推为数学正确率或所有下游任务都会提高。

工程上应将“便宜学生能否替代昂贵教师”视为按任务分布验证的问题。
高风险、少见或明显超出训练覆盖的输入，可以保留更强系统作为回退路径。
这是部署建议，课件没有规定唯一的路由算法。

## 11. 缩短 reasoning：奖励设计要保护正确性

### 11.1 第 30–31 页：冗长不总有价值

第 30 页以一个极简单加法任务却产生长推理的截图引出 overthinking。
它只是动机示例，不是“长推理普遍无用”的证据。

第 31 页对比仅按正确与否给常数 reward，和随长度变化的奖励曲线。
正确答案越长，正奖励可以下降；错误答案则使用不同的负奖励曲线。
不能忽略后者，只把整张图总结成“越短奖励越高”。

一种便于分析但不代表该图精确公式的目标是：

$$
R(y)=\mathbf1[\operatorname{correct}(y)]-\lambda |y|.
$$

它暴露了风险：$\lambda$ 太大时，模型可能偏好短而错的答案，甚至提前结束。
因此长度惩罚、正确性奖励、失败处理必须一起设计。

### 11.2 第 32 页：预算内完成才算成功

另一类方法不连续奖励每个少生成的 token，而是设置长度预算 $L$。
课件的硬预算形式可以整理为：

$$
R(y,x;L)=
\begin{cases}
1,&\text{在 }\operatorname{clip}(y,L)\text{ 中提取到正确最终答案},\\
0,&\text{否则}.
\end{cases}
$$

关键不是“完整输出后来是否答对”，而是预算截断之前有没有形成可解析且正确的答案。
尚未完成的推理不会因为它看起来接近完成就自动获得成功 reward。

第 32 页列出三种设置预算的方式：按任务类别、在 prompt 中指定预算、训练中逐渐减小预算。
课件分别列举 Kimi-K2、L1、ThinkPrune；这里仅保留课件中的例子，不补写未展示的训练细节。

硬预算通常没有区分两个都在预算内完成的正确解：一个用 100 token，一个用 500 token，二者可以同为 1。
它优化的是“在限制内完成”，不等价于直接最小化期望长度。

## 12. ThinkPrune：学习在更短预算内完成，而不只是提前拔电

### 12.1 第 33–34 页的方法与曲线

[ThinkPrune](https://arxiv.org/abs/2504.01296)使用带 token 上限的 RL，并逐轮缩小上限。
超过预算而未形成完整答案的轨迹得不到正确性奖励。
这使模型必须调整推理过程，而不仅是把旧的长输出截断。

第 33 页的示例与第 34 页的曲线比较了训练后压缩与推理时强行限长。
在若干预算区间，经过训练的模型以更短长度维持较好表现。
但越压越短仍可能明显损失质量；这些图展示的是 trade-off 曲线，不是无损压缩定理。

训练中的逐步收紧相当于给策略适应空间。
一开始就使用极小上限，可能几乎所有样本都得到零奖励，难以提供有用的正确性学习信号。
这是机制分析，具体课程安排应以实验设置为准。

### 12.2 第 35–36 页：行为发生了什么变化

第 35 页显示，反复重新检查或怀疑的短语在压缩后更少出现。
第 36 页把行为分成计算、重构问题、复查、最终整理等类别，显示它们的占比改变。

一种直觉是：模型将更多预算用于推进求解，减少反复回到已处理步骤。
但不能由短语频率下降就证明所有被删步骤都冗余，或某个短语本身导致低效率。
这些是行为相关性证据，不是单词级因果消融。

压缩后还要特别检查多步难题。
在简单题上看似重复的 verification，在困难题上可能是发现错误的唯一机会。

## 13. 不做 RL：可变长度 SFT 与简洁推理提示

### 13.1 第 37 页：展示不同 reasoning effort

如果训练数据只有极长轨迹，模型可能学不到按任务难度灵活分配预算。
课件提出为 SFT 提供不同长度的推理：

1. 使用支持多个 reasoning effort 的教师生成不同版本。
2. 将长链压缩到不同程度。
3. 同一题采样多条链，再挑选最短的正确链。

这里的关键词是“正确链”，不是单纯“最短链”。
压缩还可能删除必要前提或把不成立的推导隐藏掉，因此需要重新校验压缩后的答案与关键推导。

如果给学生输入预算标签 $b$，可训练条件策略 $Q_\theta(y\mid x,b)$。
部署时再根据任务或成本目标选择 $b$。
这是将课件想法具体化的分析，不代表普通 SFT 自动得到精确 token 控制。

### 13.2 第 38 页：让回答简短，不一定让推理便宜

“简洁回答”可能只影响最终向用户展示的文字。
若系统内部仍生成很长的 reasoning，最终答案变短不代表总输出预算下降。
评估要记录全部可计费/可统计推理 token，而不是只数答案段落。

还要区分“解释写得短”与“计算步骤减少”。
符号化草稿可能在保留步骤的同时减少文字；强制跳步则可能删除必要计算。

### 13.3 第 39–40 页：Chain of Draft

Chain of Draft 要求每一步只保留极简草稿，课件提示中使用每步至多 5 个词的限制，再输出最终答案。
它尝试压缩表达，而不是要求直接无步骤猜答案。
来源是 [Chain of Draft](https://arxiv.org/abs/2502.18600)。

第 40 页的总结是：部分设置下，以明显更少的 token 达到接近 CoT 的表现；few-shot 和更强模型的效果更好。
因此不能把它当作对任何模型、任何任务都稳定有效的万能 system prompt。
模型必须能够用简短中间表示承载足够的信息，较弱模型可能反而需要更多显式展开。

## 14. 为什么“删掉看似没信息的文字”也可能伤害 reasoning

### 14.1 第 41 页不是只给一种答案

课件同时列出缩短推理可能不伤害、甚至改善的场景：避免超过上下文上限、减少过长推理中的级联错误。
也明确指出：很多 reasoning 任务中，缩短会实证地降低性能。

所以需要的是按任务测曲线，而不是先选择“长链派”或“短链派”。

### 14.2 第 42–46 页研究的是提示示范中的推理步骤

这些页面引用 [Jin 等：The Impact of Reasoning Step Length on Large Language Models](https://aclanthology.org/2024.findings-acl.108/)。
其关键实验对象是 CoT demonstration：在尽量控制其他因素时，扩展或压缩示范中的推理步骤。
不能把它直接改写成“某个在线模型的隐藏推理每删 10% 就下降多少”。

第 42 页展示表现随步骤数改变，收益与任务有关，也并非无限增长。
第 43 页说明扩展可以包括重读、重述状态、验证和列式，而不一定增加新的题目信息。
第 46 页的压缩对比说明：保留核心事实、但减少步骤展开，也可能降低后续任务表现。

### 14.3 错误 rationale 的实验不能误读

第 44 页给出修改示范推理的例子；第 45 页比较使用正确/错误推理示范的结果。
某些条件下，含错误 rationale 但保持展开结构的示范仍能产生相近效果。

这不是允许当前任务胡算的证据。
被扰动的是 prompt 中的示范，评估的是模型随后解决新问题的表现。
它支持“CoT 提示的结构/长度本身可能影响行为”，不证明推理内容真实与否无关紧要。

### 14.4 一个适合 AI Infra 的解释

从自回归计算看，增加中间 token 会增加顺序计算机会，也会改变后续 token 可读到的上下文状态。
语义上重复的文字，不一定在计算上完全冗余。

但多计算并不自动有益：模型也可能沿着错误状态继续扩展。
因此真正目标是提高单位成本带来的有效计算，而不是机械压低文本长度。
这属于本文对课程机制的综合理解，不是课件给出的计算复杂性定理。

## 15. 一个可实现的离线蒸馏流水线

以下伪代码是本文工程整理，不是官方仓库代码，也未声称已运行训练实验：

```python
def make_distillation_record(x, teacher_system, judge):
    candidates = teacher_system.sample(x, n=16)
    valid = [y for y in candidates if format_valid(y)]
    if len(valid) < 2:
        return None

    # judge 可以是 QE、任务验证器，或包含参考集合的 MBR scorer
    scores = judge.score_all(x, valid)
    order = sorted(range(len(valid)), key=lambda i: scores[i])
    worst, best = order[0], order[-1]
    if scores[best] - scores[worst] < min_margin:
        return None
    return {
        "input": x,
        "chosen": valid[best],
        "rejected": valid[worst],
        "teacher_config": teacher_system.versioned_config(),
        "judge_config": judge.versioned_config(),
        "generation_tokens": sum(token_count(y) for y in candidates),
    }
```

实现时至少保留候选生成配置、筛选分数、长度、失败原因和数据来源。
否则质量退化时很难区分是教师更新、scorer 更新、采样温度还是训练超参数造成的。

`format_valid` 不代表事实正确；`min_margin` 也不代表已排除 judge 偏差。
训练与最终评估尽量使用不同来源的质量信号，防止只学会讨好同一个 evaluator。

## 16. 怎样判断离线蒸馏是否值得

以下是工程成本摊销，不是课件原公式。
设生成教师数据与训练的额外一次性成本为 $C_{\rm offline}$。
昂贵系统和学生系统每次请求成本分别为 $c_T,c_S$，且 $c_T>c_S$。

$$
M_{\rm break-even}
=\frac{C_{\rm offline}}{c_T-c_S}.
$$

若需要频繁重训，还要按更新周期摊销，不能假设一次训练永久有效。
对于输入分布快速变化、请求量很少的任务，在线搜索可能比维护学生模型更合算。
对于高重复、大吞吐、可稳定评估的任务，蒸馏的固定成本更容易被摊薄。

比较实验至少包含四个运行点：

1. 原模型 + 便宜解码。
2. 原模型 + 昂贵教师推理。
3. 蒸馏模型 + 便宜解码。
4. 蒸馏模型 + 昂贵解码。

这同时回答：推理是否有用、蒸馏吸收多少、蒸馏后还是否值得继续搜索。
还要报告训练成本、平均与尾延迟、所有模型 token、质量以及任务分组结果。

## 17. 自测题与面试式回答

> [!note] 来源说明
> 以下为根据课件构造的复习题，不是课堂录音中的师生问答。

### 1）两种方案都生成 8,000 token，为什么成本仍可能不同？

**回答：** Token 数只是代理。模型尺寸、输入/输出比例、缓存命中、上下文长度、并行度和外部 scorer 都影响成本。8000 个串行 token 与多个并行短链的关键路径也不同。应同时比较总 token、GPU 时间或金额、显存以及延迟，不能只看最终回答长度。

### 2）序列蒸馏和 logits 蒸馏分别需要什么信息？

**回答：** 序列蒸馏只需教师输出文本，通过 NLL 训练学生，因此能使用黑盒 API。Logits 蒸馏还需教师在每个上下文的分布，提供软标签信息，但通常要求 token 空间可对齐。前者若只选最好样本，学到的是筛选后的分布，而不是教师原始采样分布。

### 3）为什么 forward KL 常被称为 mode-covering？

**回答：** KL 中由教师概率加权；教师高概率区域若被学生赋予很低概率，会产生较大损失。受限学生往往需要覆盖多个教师模式。Reverse KL 由学生概率加权，更强调避免学生进入教师低概率区域。但这只是受模型族和优化条件影响的直觉，不是每个问题都会出现固定模式。

### 4）同一模型能给自己蒸馏出更强的学生吗？

**回答：** 可以，因为教师可以是同一模型加更强推理策略。多采样和高质量选择器可能找到普通 greedy 很少输出的好答案，训练再提高这些答案的概率。新增信号来自候选选择或效用评价，不是从完全没有监督的重复中自动创造正确知识。

### 5）QE 与 MBR 蒸馏有什么不同？

**回答：** QE 对输入和单个候选直接评分；MBR 以候选相对伪参考集合的平均效用作选择。二者都能产生 NLL 标签或 DPO 偏好对，但优化的质量信号不同。朴素 MBR 往往还要做两两比较，离线成本比逐候选 QE 更高。

### 6）为什么蒸馏后再加 MBR 不一定更好？

**回答：** 学生可能已吸收同一选择器的大部分偏好，继续选择未必提供互补信息。训练还改变候选分布，重复选择可能放大指标偏差。课件翻译表里确有这种结果，但不能当作普遍定理；应该独立测量蒸馏后各种解码器的质量—成本曲线。

### 7）为什么不把所有微小排名差异都变成 DPO 偏好？

**回答：** 排名接近的候选可能几乎等价，次序还可能来自 scorer 噪声。更多偏好对会增加训练量，却不一定增加可靠信号。课件 CP 策略在较多候选时表现更差。可比较极端、中间、步长配对，并验证分差、任务覆盖与最终泛化。

### 8）硬 token 预算与线性长度惩罚有何区别？

**回答：** 硬预算奖励“在截止前给出正确答案”，预算内两个不同长度的正确输出可得到相同 reward。线性惩罚会持续偏好更短输出，但惩罚过大可能让短错误答案优于长正确答案。二者的学习信号和 reward hacking 风险不同，不能只统称为少生成 token。

### 9）ThinkPrune 与直接截断旧模型有什么区别？

**回答：** 直接截断不改变策略，可能在答案前中止；ThinkPrune 在有限预算内进行 RL，让模型重新组织推理以赶在预算前正确完成，并逐步收紧预算。训练后的长度—质量曲线可优于单纯强行限长，但预算过小仍会损失质量。

### 10）让模型“回答简洁”能保证推理成本下降吗？

**回答：** 不能。它可能只缩短最终回答，内部 reasoning 仍很长。必须统计全部推理 token 与真实延迟。Chain of Draft 更直接约束中间表达，但效果仍依赖模型、任务和示范；表达更短也不自动意味着保留了所有必要计算。

### 11）错误 CoT 示范也有用，能否推出推理正确性不重要？

**回答：** 不能。研究扰动的是提示中的示范 rationale，再观察新任务表现，并不是允许当前答案胡算。结果说明示范的结构和展开长度也影响模型行为。当前任务仍必须用独立正确性标准评价，不能把提示效应等同于逻辑推理真伪无关。

### 12）怎样判断应该蒸馏，还是继续用昂贵在线推理？

**回答：** 先在目标任务上确定学生是否达到质量底线，再比较每请求节省与离线数据、训练和维护成本。高请求量、稳定分布通常更容易摊销；少量或快速变化任务未必划算。还应报告尾延迟、失败类别和更新频率，而不是仅用单次 token 节省决定。
