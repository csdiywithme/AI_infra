# Lecture 15：Inference Scaling vs Model Size

> [!abstract] 核心主线
> “大模型少算”和“小模型多算”谁更好，不存在脱离任务与预算的统一答案。本讲从 Pareto frontier 出发，把模型大小、生成 token 数、候选数、选择策略和每 token 额外计算放进同一个资源分配问题。实验曲线描述特定模型与方法的收益，而不是无限算力必然换来无限能力。

## 1. 本讲把前面的算法重新组织成预算问题

来源：课件第 3 页。

前面已见过增大 beam、可控生成 adaptor、Self-Refine、CoT、BoN 和 MBR。这些方法增加的计算不相同：

- 更多候选：增加覆盖的解法；
- 更长轨迹：增加单条路径的中间计算；
- 更强验证：改善候选选择；
- 更多修订：利用反馈改变下一轮生成；
- 更大模型：提高每次模型调用的能力，也改变每 token 成本。

因此“用了更多 token”并不能解释全部质量收益。需要问增加的计算发生在哪里、改变了什么，以及是否有更便宜的替代配置。

## 2. AlphaCode：大规模生成之后还要选择

来源：课件 4–7 页。

课件以 AlphaCode 的竞争编程结果说明：大量生成候选、用测试过滤、进一步选择，是一种系统级能力，而不只是单次模型输出。

阅读这类曲线时要区分：

1. 生成了多少程序；
2. 通过已有测试的程序有多少；
3. 最终允许提交多少份；
4. 这些提交在隐藏测试上的成功率。

“N 个样本中存在正确程序”与“系统成功挑出并提交它”是不同指标。测试过滤也只能证明已测性质，不能直接代替隐藏测试正确性。

本讲重要的不是记一个样本量纪录，而是看到 generator、filter、selector 和计算预算共同形成性能曲线。

## 3. Pareto optimal：不存在同时更便宜又更好的已知配置

来源：课件 8–9 页。

设配置 $a$ 的成本与准确率为 $(C_a,Q_a)$。如果另一个配置 $b$ 满足：

$$
C_b\le C_a,\qquad Q_b\ge Q_a,
$$

且至少一个严格不等，那么 $a$ 被 $b$ 支配。

没有被已评测配置支配的点构成 Pareto frontier。

### 3.1 一个最小例子

以下数字为教学构造：

| 配置 | 单题耗时 | 准确率 | 判断 |
| --- | ---: | ---: | --- |
| 小模型单次 | 1 s | 50% | Frontier 上 |
| 小模型多候选 | 4 s | 70% | Frontier 上 |
| 大模型单次 | 6 s | 75% | Frontier 上 |
| 小模型盲目加长 | 5 s | 65% | 被第二行支配 |

预算 4 秒时第二行最好；要求至少 74% 时只有第三行达标。不能无条件说第二行或第三行是“最优模型”。

### 3.2 Frontier 不是永恒属性

更换硬件、增加一个新模型、改进 scheduler、换任务指标，都可能改变边界。

课件强调最优性仅相对于当前考虑的配置空间和目标。如果只比较三种方法，不能据此宣称所有推理方法中已达到全局最优。

### 3.3 图的横轴需要读清

课件第 8 页复用 AlphaCode 图，横轴是 sampling TPU-seconds per problem，而旁边问题用了“seconds to answer”的简写。

**设备累计计算秒数不自动等于用户等待的墙钟秒数**。只有执行资源与并行假设明确时，才能从计算成本转换成实际延迟。

## 4. 四种不同的成本口径

来源：课件 10–12 页；下面的成本式为教学展开。

### 4.1 在线 FLOPs

粗略考虑主要线性层，生成成本受激活参数量 $N_{active}$、每条输出长度 $L_{out}$、候选数 $K$ 影响：

$$
C_{gen}\approx 2N_{active}K L_{out}.
$$

这里只是大致 accounting。实际总量还包括 prefill、attention、验证器、工具、修订和失败重试；MoE 总参数不等于每 token 激活参数。

### 4.2 包含训练的总成本

若部署处理 $R$ 次请求：

$$
C_{lifetime}=C_{train}+\sum_{i=1}^{R}C_{infer}(x_i).
$$

更大的训练投入可能被大量请求摊薄。只做几次高价值离线任务，与每天服务大量请求，最优配置可能不同。

### 4.3 延迟

$K$ 条独立候选有并行空间；一条长 CoT 或多个依赖修订轮通常有串行依赖。

同样花费 10000 个 output tokens，十条并行轨迹与一条连续长轨迹的等待时间可以相差很大。

### 4.4 显存与可部署性

参数、KV cache、候选分支、judge、workspace 共同决定能否放进设备。

一个 FLOPs 更低的配置，可能因为模型放不下而根本不可行。课件第 11 页为讨论便利假设所有模型都能装下；工程决策不能忘掉这个假设。

## 5. Compute-optimal inference 的数学定义

来源：课件 13–16 页，对应 Wu et al. 的研究。

记 $E(N,T;S)$ 为模型规模 $N$、生成预算 $T$、策略 $S$ 的错误率。给定预算 $C$：

$$
(N^*,T^*,S^*)\in
\arg\min_{N,T,S:\ \mathrm{FLOPs}(N,T;S)\le C} E(N,T;S).
$$

课件用预算等式展示曲线上同成本比较；这里写成不超过预算，允许最优配置没有必要用完所有资源。

### 5.1 不只调候选数

只对一个固定模型增加 N-samples，得到的是一条曲线，不是整个最优解。

完整比较至少包含模型大小、策略、候选数、轨迹长度和验证器成本。有时小模型多次采样更合算，有时大模型的能力差距无法由现有策略补足。

### 5.2 课件第 16 页的两个视角

左图横轴 FLOPs、纵轴 test error：在同成本处比较谁更低。

右图横轴模型大小、纵轴 test error，颜色表示 FLOPs：同一个模型大小可以通过不同推理预算得到多个点。只比较模型名字会漏掉整个推理配置维度。

原论文研究了多种策略与模型大小的组合，结论应保留其任务和实验范围。[Wu et al. 原论文](https://arxiv.org/abs/2408.00724)

## 6. 为什么多数投票会达到平台？

来源：课件 17–20 页。

设生成轨迹为 $(r,y)$，$y$ 为抽取并规范化后的答案，其答案边缘概率：

$$
p_x(y)=\sum_rP(r,y\mid x).
$$

从同一策略独立采样 $K$ 次，频率估计为：

$$
\hat p_K(y)=\frac1K\sum_{i=1}^{K}\mathbf1[y_i=y].
$$

在固定分布、适当有界/有限设置及唯一 mode 等条件下，样本增多后，投票趋向概率最大的答案。

但那个答案不一定正确。

### 6.1 多采样可以更稳定地答错

教学例子：正确答案概率 0.40，某个错误答案概率 0.60。增加样本后，投票越来越稳定地选错误答案。

反过来，若正确答案概率 0.40，两个错误答案分别 0.35 和 0.25，正确答案虽未超过 50%，仍是三类中的 mode。

这里常称 majority voting，实际通常按最大票数（plurality）选出答案，不要求绝对过半。

### 6.2 数据集上的极限

若每题都有唯一 mode，极限准确率为：

$$
\frac1m\sum_{j=1}^{m}
\mathbf1\left[y_j^*=\arg\max_y p_{x_j}(y)\right].
$$

它由模型诱导的答案分布决定。无限采样主要消除了 Monte Carlo 误差，不自动消除模型偏差。

若有并列 mode，需要额外讨论 tie-breaking 与采样极限；不能无条件沿用唯一胜者的结论。

### 6.3 Weighted voting 改变被聚合的量

用权重 $w(x,r,y)$ 给每条轨迹投票，极限比较的是：

$$
g_x(y)=\mathbb E_{(r',y')\sim P}
\left[w(x,r',y')\mathbf1[y'=y]\right].
$$

需要权重可积等条件。它不再只由原始答案频率决定，因此强评分器有可能改善平台；错误评分器也会引入自己的偏差。

“普通投票有平台”不等于所有推理策略共享同一个不可突破的上限：换分布、验证器或交互策略，已经改变问题设置。

## 7. 难度感知：同一笔预算不该总用同一种方法

来源：课件 21–25 页。

Snell et al. 比较迭代修订以及用 process reward model 引导的搜索。课件第 22 页显示不同方法的相对表现随预算变化。

第 23–24 页进一步按模型对题目的初始成功率分难度组；这种难度是相对于模型的，不等同于题目人工标签。

容易题、尚有一定成功机会的中等题、几乎从不成功的题，对额外预算的反应不同。

### 7.1 不能把难度标签当部署时免费可得

离线可以用真实答案和多次采样估计 pass@1，再构造 oracle difficulty bins。

真实请求尚不知道正确答案，通常拿不到这种完美难度信息。需要预测难度、利用早期观测，或者用便宜策略先探索。

难度预测错了会产生调度成本：把本来容易的请求过度计算，或让难题过早停止。路由器也应作为系统的一部分评测。

### 7.2 什么结论可以迁移？

可迁移的是“按难度和预算分配策略”的思路，不是把某张数学题曲线上的阈值直接部署到所有任务。

原论文在特定 FLOPs 匹配与成功率条件下，展示小模型加推理计算可以胜过更大模型；不构成任意任务上的替代保证。[Snell et al.](https://arxiv.org/abs/2408.03314)

所以正确解读是：

## 9. 评价 agent，要评价整个系统

来源：课件 27–29 页。

两个系统都使用同一个底座，不意味着成本接近。它们可能使用不同候选数、工具、judge、retry、轨迹长度和上下文。

只报成功率会奖励无限重试或昂贵搜索，无法回答“同一预算下哪个设计更好”。

本讲建议把质量与成本一起看。工程上还应加上错误条、失败率，以及任务分布，避免平均值掩盖高成本长尾。

### 9.1 Token budget 应包含失败支路

只统计最终答案 token，会把搜索中被丢弃的轨迹、judge 输出和工具观察隐藏掉。

若系统使用缓存优惠、批处理或不同模型服务，API token 数、账单金额和本地 FLOPs 也应分开记录。

## 10. ParScale：多做 forward，不必多写 reasoning tokens

来源：课件 30–35 页；补充核对[原论文](https://arxiv.org/abs/2505.10475)。

ParScale 为输入构造 $P$ 条不同且可学习的变换路径，共享主模型参数进行并行计算，再动态聚合输出。

课件示例是可学习 soft prompts，以及预测各分支权重的聚合模块。随机初始化只是起点，不意味着整个过程无需训练。

### 10.1 与 BoN 的区别

BoN 通常生成多个完整候选，再选择一份答案。

ParScale 在模型计算内部组合多个并行路径，形成最终预测；它不是简单地采 P 条完整回答后投票。

### 10.2 Scaling law 如何理解

论文把增加并行流数的效应与参数扩展联系起来，给出与 $\log P$ 相关的 scaling 关系，并通过训练实验拟合。

课件写 $O(N\log P)$，应结合“参数规模 $N$ 与扩展倍数”的语境读，而不是当成可对任意 P、任意模型直接代入的精确参数换算式。

尤其不能用 $P=1$ 时 $\log P=0$ 推出模型等效为零参数；基线、常数项和拟合范围都不能省略。

### 10.3 工程收益的边界

共享权重可能比复制成更大模型节省参数存储；并行执行可能比串行延长轨迹更低延迟。

但分支激活、缓存、聚合和额外 FLOPs 不免费。输入变换不同的流一般不能只共享一份完全相同的 KV；每个固定流仍可能维护自己的缓存，不等于每一步都必然全部重算。

## 11. HARP：高熵位置额外看一遍

来源：课件 36–40 页；补充核对[作者实现说明](https://github.com/romsto/HARP)。

流程：先做原始 forward，判断下一 token 分布是否足够不确定；若超过阈值，对输入 embedding 做 dropout，再跑一次并组合输出。

### 11.1 熵属于概率分布，不属于未归一化 logits

设 $p=\operatorname{softmax}(z)$，则：

$$
H(p)=-\sum_vp(v)\log p(v).
$$

课件的“logit distribution entropy”应理解为从 logits 得到的 token 分布之熵。

高熵可能来自多种合法措辞，不一定说明事实推理困难。它是资源分配的启发式信号，不是任务正确率的直接估计。

### 11.2 教学伪代码

```python
def reframed_logits(tokens, model, theta, delta, beta):
    z = model.forward_logits(tokens)
    p = softmax(z)
    if entropy(p) <= theta:
        return z
    e = model.embed(tokens)
    z2 = model.forward_from_embeddings(dropout(e, delta))
    return (1 - beta) * z + beta * z2
```

这只是控制流程，省略 batch、数值稳定性和缓存管理；不是可直接替换任意模型 forward 的生产实现。

### 11.3 为什么额外 forward 会影响串行延迟？

必须等第一次 forward 给出熵，才能决定是否执行第二次。这个条件计算链不是全部提前并行。

课件以每步一遍或两遍说明调用数量，但当原本的 KV cache 因输入扰动失效时，第二遍可能处理更长上下文。不能据此保证相对缓存基线的端到端耗时永远不超过两倍。

## 12. IMPACT：保留 cache，改变额外计算路径

来源：课件 41–44 页；相关原文为 [Smarter, Not Harder](https://aclanthology.org/2025.findings-acl.426.pdf)。

HARP 改变输入 embedding，导致后续层的 K/V 也变。IMPACT 改用对网络计算的近似，通过 contextual sparsity 构造额外路径，保留原始输入及缓存。

课件把它概括为抑制对应较小激活的线性层贡献，在原 cache 上改变 residual stream 和 queries 的计算。

这里不应说“任意改模型权重后旧缓存仍精确有效”：这是特定算法明确保留基线 K/V 的近似设计，不是一般 cache 等价性定理。

### 12.1 如何读性能对比

课件第 43 页展示部分任务上的改善，但第 44 页的具体表格也说明它并非处处更准或更快：

| 方法 | LAMBADA 延迟 / EM | CNN/DM 延迟 / ROUGE-1 |
| --- | --- | --- |
| Original | 1.00× / 55.48 | 1.00× / 29.52 |
| HARP | 2.20× / 56.62 | 7.23× / 29.99 |
| IMPACT | 2.30× / 55.52 | 1.41× / 29.05 |

延迟分别相对各任务的 Original 归一化。这里 IMPACT 在 CNN/DM 上比 HARP 快得多，但 ROUGE-1 低于基线；在 LAMBADA 上也没有比 HARP 更快。表格只代表课件引用的模型和实验配置，不是跨硬件的固定倍率。

因此要比较的是新增质量 / 新增成本，而不只是“有没有再跑一遍”。也不能因为一个方法参数不更新，就认为它不改变输出分布。

## 13. 面向 AI Infra 的联合预算分配

以下为教学实验设计。

先固定任务集、硬件和质量指标，建立配置表：

| 维度 | 至少记录 |
| --- | --- |
| 模型 | 权重版本、激活参数、量化方式 |
| 生成 | 候选数、温度、每条输出上限、实际长度 |
| 选择 | RM/PRM 型号、调用数、额外 tokens |
| 系统 | 并发、batch、prefix sharing、设备数 |
| 结果 | 成功率、置信区间、TTFT、完成延迟、费用、峰值显存 |

先画准确率–FLOPs frontier，再画准确率–延迟和准确率–费用 frontier。它们不同不是实验矛盾，而是目标函数不同。

### 13.1 有限配置集合的选择器

```python
def choose_config(rows, max_cost, max_latency, max_memory):
    feasible = [r for r in rows
                if r['cost'] <= max_cost
                and r['latency'] <= max_latency
                and r['memory'] <= max_memory]
    if not feasible:
        return None
    return max(feasible, key=lambda r: (r['quality'], -r['cost']))
```

代码只是在离线测量表中选择可行配置。若数据来自测试集，不能用这段代码不断调参再报告同一测试集作为无偏泛化评估。

### 13.2 一个常被忽略的资源机会成本

单请求使用八条并行流，可能缩短该请求时间，却占用了原本可服务其他用户的容量。

低负载时多算一个请求，和高负载时为每个请求都多算，系统吞吐与排队代价不同。

所以最终部署需要 workload-level 评测，不只测一个没有竞争的离线例子。

## 14. 自测与参考回答

### Q1. Pareto-optimal 是否等于我应该选它？

不等于。Frontier 上仍有多种成本–质量取舍，必须按延迟、预算和最低质量要求选择。

### Q2. 相同 FLOPs 为什么不等于相同延迟？

计算的串行依赖、batch 大小、内存流量、设备数和硬件利用率不同；总工作量不决定关键路径长度。

### Q3. 为什么模型大小与候选数应一起调？

模型大小影响一次尝试的能力和成本，候选数影响覆盖与选择机会。在固定预算下二者互相挤占资源。

### Q4. 多数投票的极限正确率由什么决定？

在固定分布、唯一 mode 等条件下，由每题的正确答案是否恰好是模型答案边缘分布的 mode 决定。

### Q5. 正确答案概率只有 40%，投票一定失败吗？

不一定。若其他各答案概率均小于 40%，它仍是最大票数赢家；只有二分类时才能直接用 50% 判断 mode。

### Q6. 多数投票有平台，是否说明更多推理计算没用？

不是。换 verifier、调整生成分布或进行有效修订会改变算法本身；固定投票策略的极限不是所有策略的上限。

### Q7. 难度感知策略为什么部署更难？

实验中的 oracle 难度可用真值和重复采样计算，线上通常未知。路由误差和探测成本必须纳入端到端评价。

### Q8. 第 26 页星号在曲线上方说明什么？

星号是更大模型，在上方意味着更大模型准确率更高；课件该页文字把方向写反，应以原图注为准。

### Q9. ParScale 与 BoN 有何不同？

ParScale 组合模型内部多条并行计算路径；BoN 通常在完整序列层面生成多候选并选择。前者还需要相应训练支持。

### Q10. HARP 检测的 entropy 能证明模型不知道答案吗？

不能。下一 token 多种合理表达也会高熵；它只是一个触发额外计算的启发式指标。

### Q11. 为什么 HARP 与 KV cache 有冲突？

输入 embedding 改变后，深层历史 K/V 也可能改变。复用旧 cache 不再等价于对扰动输入重新执行模型。

### Q12. 用同一个基础模型比较两个 agent 就公平了吗？

还不够。需要同时计入模型调用、生成和评分 token、工具执行、重试、缓存与并行资源。
